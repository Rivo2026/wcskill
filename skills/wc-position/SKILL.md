# wc-position · 人设定位

交付一份完整的人设定位方案。让目标用户理解你能解决什么、为什么值得信任，以及什么时候值得进一步咨询或合作。既要说明商业作用，也要给出具体建议，不能以定位原则、候选清单或验证计划代替成品。

## 方法与业务流程的关系

共同愿景定位是上游判断方法：从目标人群的现实处境、希望发生的身份与能力变化，确定创作者长期提供的帮助、建立的关系和承担的责任；人设是这些帮助被持续看见后形成的稳定印象。由此推导角色、表达与呈现，并说明它们怎样服务获客、价格理解、合作选择和实际交付。

升级判断方法时，保留完整的业务流程：本人逐轮沟通，或代运营人员提交资料；随后推导人设、给出完整报告、保存文件并按反馈修订。表达示范、视觉建议、差异化、落地检查和成长路径都是独立交付，不得用愿景阐释替代。任务在定位方案及其修订范围内完成，不主动扩展交付物或执行后续制作。

## 开始工作

先读已有产品说明、客户定位、本人经历、案例、作品和旧方案。已有产品与目标人群结论可以直接承接，无需重做全部业务定位。只读取与当前任务相关的文件，使用用户已经确认的信息。

按输入情况自然推进，不让用户选工作模式：

- 本人来讨论：按 [信息收集](references/intake.md) 依次补齐业务与价格、履历实力、客户理解程度、竞争环境或自身专长，每次一个主题、一到两个问题；已提供的内容直接承接。
- 为他人制定方案：按 [信息收集](references/intake.md) 接收产品与人群资料、履历、性格表达、竞争环境，以及委托人的初步判断和疑问；随后推导草案。每项核心结论就地标明事实来源、分析判断或待验证假设，并附分优先级的验证安排。资料不全只补影响核心推荐的缺口。
- 已有人设，要求修改某一处：先定位具体问题，只更新受影响部分；不从头问履历，也不强制重交整份报告。

无法判断是在为本人还是他人制定方案，且会影响事实确认与表达可行性时，简短确认服务对象，不要求用户理解工具的模式名称。

没有产品时，从实际能提供的帮助开始，形成起步方案，不替用户编造产品、价格或客户。想做哪个方向都不清楚时，先围绕一件实际做过的事确定试行范围，再继续人设设计。

## 信息够用就给方案

标准业务输入是产品形态与实际客单价、履历实力、目标客户的理解程度、竞争环境或自身专长。代运营场景还接收本人性格和委托人的初步判断。用户已有的视频样本、成交数据及愿景表述可作为补充资料，不增加标准流程的启动门槛；已有材料能支持判断时，给出注明前提的建议。没有业务的起步分支须标明尚未验证商业定位。

已有资料足以支持核心推荐时，停止收集，读取 [推导与设计](references/decisions.md) 和 [方案交付](references/profile.md)，直接交付。用户明确要求先给初版时，用现有信息完成暂定方案，逐项写清假设；不能只回复一张待补材料表。

信息明显不足以判断业务方向、帮助对象或能力时，先问那个会改变整份方案的问题。没有视频只能推断表达偏好，不能声称听过其语气；没有现场照片也可以按已知空间提出暂定布置。

## 推导要落到呈现

内部按以下关系逐步设计，输出使用交付文件中的执行结构：

1. **从希望帮助用户发生的变化推导角色。** 承接已有产品与人群结论，用共同愿景确定持续帮助和责任，再结合购买理由、风险与服务结果，明确用户会把什么事托付给你、需要看见什么价值。
2. **决定用什么建立信任。** 从实际经历、操作过程、判断依据、结果与责任中选择证据，明确能承诺到哪里。
3. **设计本人说得自然的表达。** 把判断写成具体话术，再检查是否超出真实实力、是否符合听众理解程度。不能停在“专业、真诚、有温度”。
4. **让画面帮助观众理解。** 选择现有条件下可执行的场景、服装、道具、拍摄形式和镜头安排，解释画面在证明什么。
5. **说明差异并形成落地检查。** 对照同行或替代选择，写清个人优势、竞争留白和获客理由；分别为内容、表达关系、视觉呈现列出能逐项执行的检查。
6. **说明如何积累与调整。** 给出当前做法、下一阶段可以增加的承诺、所需依据及调整条件；需要商业承接时同时检查咨询与交付反馈。

共同愿景落实在内容和交付的取舍中：希望用户逐渐能独立完成什么、怎样帮助身边的人、创作者愿意因此承担什么责任。使用本人已有立场；尚未确定时提出可讨论的方向。不要拿抽象愿景替代话术、拍摄和成长路线。

## 完整交付要求

[方案交付](references/profile.md) 中的人设建议与表达样稿、视觉建议、独立差异化分析、分类落地清单和成长路径，都是完整方案的必交内容。为他人制定方案时，另交逐项结论依据和分优先级的验证清单。缺少条件的项目给暂定建议并说明前提，不能默默删掉。视觉建议按推荐的内容形式选择适用项；用户明确只要某一项时按该范围交付。

人设建议要说明为什么能降低顾虑、呈现能力或帮助合适的客户作选择。不得承诺换一个称号、穿一套衣服就能涨价或提升转化。案例、从业年限、营收、成交结果只能来自真实材料；拟写的话术和画面方案明确属于创作建议。

用户要求生成完整方案且当前有可写项目时，默认保存到 `人设定位/<人物或账号名>/人设执行方案.md`；用户指定路径则沿用，已有正式文件先读取再更新。姓名不明使用“当前账号”，不为取名再追问。用户仅咨询、明确不保存或环境不能写文件时，在对话交付完整方案。不要修改无关项目文件。

最后简短说明推荐人设、文件位置和关键待确认项。
