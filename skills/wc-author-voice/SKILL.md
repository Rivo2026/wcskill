# 作者思维提取

从指定作者的 15-20 篇文案中，提取其稳定的思维方式、论证逻辑和表达习惯。在内容创作的"灵感膨胀和挖源头"阶段，基于提取的"作者思维画像"，辅助用户把碎片化想法组织成有该作者"味道"的内容。

## 核心目标

**让观众从内容中获取稳定的"作者思考方式和习惯，甚至是理论流派"，从而吸引同频人群。**

不是模仿表层结构（句式、开场、转折），而是提取思维方式：
- 他怎么想（注意力焦点、因果信念、理论工具）
- 他怎么论证（推理母版、证据标准）
- 他怎么表达（概念定义、造词习惯）

## 使用场景

1. **建立稳定的个人风格**：想让自己的内容保持一致的思维方式和论证逻辑
2. **学习优秀作者**：研究某个作者的思维方式，作为参考或对标
3. **辅助内容创作**：在"灵感膨胀"阶段，基于作者画像梳理碎片、补充延伸

## 工作流程

### 阶段一：读取与分析

**输入要求：**
- 指定作者的文案来源（CSV 文件路径）
- 篇数：15-20 篇（建议按播放量排序）
- 预期语料：3-4 万字

**读取步骤：**
1. 读取 CSV 文件，提取"视频文案"字段
2. 按播放量排序，取前 N 篇（默认 20 篇）
3. 统计总字数，确认在 3-5 万字范围内
4. 如果超出 5 万字，提示用户减少篇数

### 阶段二：提取作者思维画像

按以下维度提取，分为**思维层**和**表达层**：

#### 思维层（核心）

**1. 认知框架**
- **注意力焦点**：他关注什么、忽略什么
  - 从文案中看他总是谈什么话题、从什么角度切入
  - 什么话题从不涉及、什么角度从不考虑
- **重要性排序**：多个维度冲突时他优先哪个
  - 理解 vs 行动
  - 原理 vs 方法
  - 本质 vs 表象
  - 过程 vs 结果
- **因果信念**：他相信什么导致什么
  - 努力 → 结果？
  - 选择 → 结果？
  - 认知 → 结果？
  - 时机 → 结果？

**2. 论证逻辑偏好（按系列）**

一个作者的账号可以看作一个频道，频道下有多个系列，每个系列有自己的论证/推进共性。

需要识别：
- 该作者有哪些系列（不只是"内容类型"，而是他稳定输出的几个系列）
- 每个系列的特征：选题模式、论证逻辑、推进方式

**提取格式：**

对每个系列：
- **系列名称**（如：批判行业共识系列、方法论讲解系列、概念澄清系列、资源推荐系列）
- **系列特征**：
  - 选题模式（这个系列总是选什么样的话题）
  - 思考方式（在这个系列中的核心思维模式）
  - 推理母版（惯用的推进路径和步骤）
  - 论证的跳跃性（会不会突然换角度、插入其他内容）
  - 补充的随意性（讲完一个点会不会突然想起另一个）
  - 收束方式（一次性收束，还是来回兜圈）
  - 证据标准（什么算证据）
- **典型案例**：从文案中摘录该系列的 1-2 篇完整案例

**3. 概念使用习惯**
- **关键词的独特定义**：他对某些词的重新定义（如"悬浮人群""意识形态定位"）
- **造词习惯**：爱造新词、重定义旧词、还是用常见词
- **抽象 vs 具象**：抽象概念和具体案例的比例，以及它们在论证中的位置

**4. 理论工具偏好**
- **常用理论/框架**：他习惯用什么理论作为分析工具（社会学、心理学、哲学、商业理论）
- **使用方式**：直接引用、降维应用、还是只借概念
- **在论证中的位置**：开场框架、中间验证、还是结尾升华

#### 表达层

**5. 论证习惯**
- 从什么角度切入
- 如何展开
- 如何收尾

**6. 开场套路**
- 钩子类型（批判共识、反常识、讲故事、直接亮观点）
- 信息缺口制造方式

**7. 转折手法**
- 如何推进论证
- 如何制造"但是"
- 如何处理反例

**8. 句式偏好**
- 长短句比例
- 口语化程度（完整度、是否有口误感、是否有语法不完整）
- 重复模式（重复关键词、重复句式）
- 句子结构（是否一句话里不断补充、转折、举例）
- 推进节奏（是否随意、是否突然打断、是否不断拐弯）
- 段落结构（是否清晰分段、还是模糊推进）

### 阶段三：呈现作者思维画像

**呈现原则：**
- 在对话中展示，不写入文件
- 只展示提取结果，不展示分析过程
- 每个维度给出具体特征 + 典型案例（从原文摘录）

**呈现结构：**

```
## [作者名] 的思维方式画像

### 一、认知框架
1. 注意力焦点
   - 关注：[具体内容]
   - 忽略：[具体内容]
   - 典型案例：[原文摘录]

2. 重要性排序
   - [维度对比] → 他优先 [哪个]
   - 典型案例：[原文摘录]

3. 因果信念
   - 他相信：[具体因果关系]
   - 典型案例：[原文摘录]

### 二、论证逻辑偏好（按内容类型）

**内容类型 A：[类型名称]**
- 思考方式：[描述]
- 推理母版：[步骤]
- 证据标准：[什么算证据]
- 典型案例：[原文摘录]

**内容类型 B：[类型名例]**
- 思考方式：[描述]
- 推理母版：[步骤]
- 证据标准：[什么算证据]
- 典型案例：[原文摘录]

[如果有更多内容类型，继续列出]

### 三、概念使用习惯
1. 关键词独特定义
   - [词] → [他的定义]
   - 典型案例：[原文摘录]

2. 造词习惯
   - [描述]

3. 抽象 vs 具象
   - [比例和位置]

### 四、理论工具偏好
- 常用理论：[列出]
- 使用方式：[描述]
- 在论证中的位置：[开场/中间/结尾]
- 典型案例：[原文摘录]

### 五、表达层特征
[简要列出论证习惯、开场套路、转折手法、句式偏好]

---

**画像提取完成。现在你可以丢碎片灵感，我会基于这个画像帮你梳理、补充、组织成提纲或草稿。**
```

### 阶段四：互动模式

用户丢碎片灵感后：

**1. 判断内容类型**
根据用户的碎片灵感，判断它属于哪个内容类型（基于阶段二提取的内容类型分类）。

**2. 调用对应的思维方式和表达习惯**

**必须同时调用思维层和表达层：**

**思维层（怎么想、怎么论证）：**
- 该内容类型下的思考方式
- 推理母版（按步骤展开）
- 证据标准
- 概念使用习惯（用作者的独特定义和造词）
- 理论工具（在合适位置引入）

**表达层（怎么说）：**
- 论证习惯（从什么角度切入、如何展开、如何收尾）
- 开场套路（用作者的典型钩子类型）
- 转折手法（用作者的推进方式和"但是"制造方式）
- 句式偏好（模仿长短句比例、口语化程度、重复模式、口语标记词）

**重点：表达层不是装饰，是让内容"像作者"的关键。必须充分应用。**

**3. 提供输出**

给用户两个选项：

**选项 A：提纲 + 提醒**
- 基于作者的思考方式和推理母版，把碎片整理成结构
- 标注哪里需要用户自己说、哪里可以用作者的典型手法、哪里需要补充论据
- **格式要体现作者的论证习惯和转折手法，不要用标准的"一二三"结构**
- 示例：
  ```
  ## 提纲
  
  开场：[用作者的典型开场套路]
  - [具体钩子]
  - 💡 提醒：这里用作者的"批判共识"开场，直接制造认知冲突
  
  拆解前提：[按作者的推理母版展开]
  - [隐含前提是什么]
  - [用什么方式推翻]
  - ⚠️ 需要你补充：[具体的边界案例或反例]
  
  收尾：[用作者的收尾方式]
  - [说明立场和边界]
  ```

**选项 B：草稿正文**
- **直接用作者的表达方式写成口播稿，必须体现：**
  - 作者的口语标记词（"就是说""那么""对吧""什么意思呢"）
  - 作者的句式节奏（长短句比例、停顿位置）
  - 作者的转折手法（怎么用"但是""问题在于"推进）
  - 作者的重复模式（重复哪些关键词）
- 用户需要修改，不能直接用
- 标注：这是基于你的碎片 + [作者名]的思维方式和表达习惯组装的草稿，请修改后使用

**4. 持续互动**
- 用户可以继续补充碎片、修改方向、要求调整
- 每次调整都基于作者画像（思维层 + 表达层）
- 全程在同一窗口

## 边界和约束

### 1. 语料规模
- 建议：15-20 篇，3-4 万字
- 上限：不超过 5 万字（占用约 10 万 tokens，留 10-12 万 tokens 给后续对话）
- 超出提示用户减少篇数

### 2. 输出形式
- 全程在对话中，不写入文件
- 不创建 markdown 文件
- 不保存到本地

### 3. 内容边界
- 用户的碎片 + 作者的习惯 → AI 组装 → 用户修改
- 不是 AI 原创，是基于用户材料的组装
- 草稿必须由用户修改后才能使用

### 4. 提取质量
- 思维层（认知框架、论证逻辑、概念使用、理论工具）是核心，必须充分提取
- 表达层（论证习惯、开场、转折、句式）是辅助，简要提取即可
- 每个维度必须有具体特征 + 典型案例
- 不能只给抽象标签（如"喜欢用类比"），必须说明在什么情况下、如何使用

### 5. 内容类型识别
- 必须从文案中归纳出该作者的内容类型分类
- 不能用预设的分类（如"批判/讲方法/推荐"）硬套
- 每个内容类型必须有明确的特征和推理母版

## 调用时机

### 独立调用
用户直接调用 wc-author-voice，提供文案来源，提取作者思维画像后进行互动。

### 被 wc-content-prep 调用
在 wc-content-prep 的"膨胀和挖源头"阶段，可以调用 wc-author-voice 获取作者思维画像，用于辅助梳理用户的碎片想法。

**调用方式：**
用户在 wc-content-prep 中明确表示"用 XX 作者的思维方式"或"对标 XX 作者"时，提示用户是否调用 wc-author-voice。

## 完成标准

**阶段二（提取）完成标准：**
- 四个思维层维度全部提取完成
- 每个维度有具体特征 + 典型案例
- 内容类型分类清晰，每个类型的思考方式和推理母版明确
- 表达层四个维度简要提取

**阶段四（互动）完成标准：**
- 基于用户碎片生成的提纲或草稿，体现了作者的思考方式和表达习惯
- 用户确认可以使用（或继续修改）

## 注意事项

1. **不要过拟合**：提取的思维方式应该跨话题适用，不要只针对特定话题的特定结构
2. **不要补造事实**：典型案例必须从原文摘录，不能编造
3. **不要替用户决定**：互动阶段给出提纲或草稿后，由用户决定是否使用或如何修改
4. **不要写文件**：全程在对话中，除非用户明确要求保存
5. **不要混淆作者**：如果用户提供多个作者的文案，分别提取，不要混在一起
