# 开头打磨（框架试用版）

目录及调用名暂用 `wc-hook`，名称尚未作为最终交付确认。属于 wcskill 第三阶段：先有正文，再写开头。

当前完成的是可独立读取的提示词框架，不是已验证的完整 Skill。只有 FS-001 进入本轮试写；其原文选择与主要分析已有讨论依据，最新生成规则仍需独立窗口验证。不要把尚未完成的其他样本当作现成范例。

## 开头的定义

**开头 = 0-2s区间 + 好奇区间 + 引子**（正文之前的所有部分）

| 区间 | 核心作用 | 在开头中的位置 |
|------|----------|----------------|
| **0-2s区间** | 注意力劫持，强制中断观众思考 | 开头第一部分（最前2秒或1-2句） |
| **好奇区间** | 堆叠素材/反差/数据，维持好奇心；**严禁剧透正文方法/结论/核心内容** | 开头主体部分 |
| **引子** | 收束悬念，承诺价值，过渡到正文 | 开头最后部分（1-3句） |

**正文从哪里开始**：引子之后，开始系统性论证/分步骤讲解/交付方法的地方。

---

### 0-2s区间

**时间范围**：时间戳落入 [0.00s, 2.00s) 的语音/文本，或纯文本时最前面的1-2句（或第一句话到第一个强钩子落点）。

**核心作用**：注意力劫持，强制中断观众思考，让观众无法划走。

**锚点切换路径分析**：按观众接收信息的时间顺序（【t1】【t2】【t3】...），逐片段标注：
- **锚点类型**（情绪锚/关键字锚/疑问锚）
- **观众心理状态**（"我会不会""然后呢""为什么"）
- **锚点传递模式**（叠加/转换/持续）
- **最终导向**（有价值/有意思）

**核心原理**：观众在低注意力状态下，必须保持一个锚点（情绪/关键字/疑问）才能继续接收信息。锚点丢失 = 观众划走。

完整分析方法见 [核心术语表 - 锚点检查清单](references/glossary.md#锚点检查清单)。

**常见接力模式 — 议题后置（垫句铺底）**：不在第一句亮出议题，而是用前面1-2句分别铺设不同的心理底色（圈人群、社会证明、评价预设等），让议题落地时观众已处于最佳接收状态，冲击力远大于直接开口说议题。

**示例**：「我不知道大家（圈人+悬念）→ 是怎么看待这两年很火的词（社会证明+评价预设）→ 高认知穷人（议题落地，悖论型认知冲突+判断缺口）」

---

### 好奇区间

**位置**：2.00s之后、引子之前，旨在驱动观众继续观看的内容。

**核心作用**：堆叠素材、反差、数据、悬念，维持好奇心，让观众想知道"接下来怎样"。

**核心手法**：
- 堆叠素材：具体对象、事件、案例
- 制造反差：预期 vs 真实、通常 vs 反常、表面 vs 背后
- 数字证明：具体数据、规模、成就
- 悬念建立：提出待解释的关系、待揭晓的身份/结果

**严禁剧透**：好奇区间只负责制造好奇、维持悬念，**严禁对正文方法/结论/核心内容进行剧透**。

**什么算剧透**：如果观众听到这个表达后，能直接接出正文要交付的关键区分/方法/机制/具体做法，就是剧透了。不只是因果句，半句话、修饰词、暗示、同义替换，也可能已经给出关键答案。

**剧透判断原则**：开头的作用是制造好奇心。好奇心 = 提出问题但答案未知。如果答案的一部分已经给出，好奇心被破坏了。开头可以让观众知道"正文讲什么话题"，但不能让观众接出"正文讲的具体是什么内容"。

---

### 引子

**位置**：好奇区间与正文之间的收束点，通常为1-3句。

**核心作用**：收束前文悬念，提出核心问题或承诺价值，过渡到正文。

**正向条件**（需尽量同时满足）：
1. 对前文素材/悬念进行语义收束（而非继续堆叠新素材）
2. 提出一个可被正文回答的核心问题或命题，或直接给出价值承诺
3. 句数通常为1-3句

**排他性规则**：
- 若该句仍在堆叠新的素材/案例/数据 → 归入好奇区间
- 若该句已开始系统性论证/分步骤讲解 → 归入正文

**常见形式**：
- 追问式："什么叫……？" "为什么会……？" "怎么会……？"
- 承诺式："随便说几个问题你就明白了" "背后隐藏着一个技巧"
- 命题式：直接提出正文要解释的核心关系或判断

---

### 区间判定原则

按信息出现顺序逐句判断：
1. 时间戳在2秒内，或纯文本的最前1-2句 → 0-2s区间
2. 仍在堆叠素材、制造反差、建立悬念 → 好奇区间
3. 开始收束悬念、承诺价值、提出核心问题 → 引子
4. 开始系统性论证、分步骤讲解、交付方法 → 正文

## 启动提示

Skill 被调用后，问用户：

**「发正文过来，我帮你写开头。」**

拿到正文后：
1. 自动调用 Jev 选择器评估匹配度
2. 根据置信度决定：
   - 置信度 ≥ 80%：直接使用推荐的 FS 生成开头
   - 置信度 50-80%：使用推荐的 FS，但提示"可能需要一定改写"
   - 置信度 < 50%：告知"所有 FS 匹配度都不高"，但仍用概率最高的尝试生成
3. 直接交付开头候选

用户没有明确要求时，不展示 Jev 评估过程、不展示车厢循环分析、不展示防剧透检查——这些是内部工作流程，只在生成失败或用户要求时才说明。

## 任务与产出

把正文中已经成立的内容组织成适合逐步听到的开头，交付少量候选、简短推荐与正文接入位置。用户指定数量时按指定数量；未指定时暂以两条为试用默认，不为凑数量编造发现。

用户只要文案时直接交付文案。不要默认展示长篇分析、机制评分或生成过程。开头可以跨数句，不凭文本声称占据真实 0—2 秒。

## 1. 承接输入

恢复已有正文、目标受众、目的、中心判断、事实边界、已确认的表达与参考要求。同一窗口已有的信息直接沿用；不重新执行内容准备。

区分三种任务：

- **正文生成开头**：以正文为内容依据，不能继承 few-shot 作者的经历、数据和结论。
- **指定样本试写**：用户已选样本时直接按该样本工作，不再次请求选模。正文不足以支持其关键关系时，指出具体缺口并提出可用的调整，不伪造因果来凑句式。
- **无正文的演示试写**：只有用户明确允许自由举例、构造样例时，先形成少量候选内容关系与假设底稿，再选定一组写开头；不要一开始锁死第一种解释。底稿包含具体发现、成立情境、解释材料与收获，标明创作假设；选定后不为迁就开头临时改写解释。若只是忘记提供正文，用一个问题索取正文或可用要点，不要求用户补齐整套表格。

## 2. 从材料中提取内容关系

写开头前，先按题材与受众估计常见原因及通常有利的条件；这份初始预期不使用拟写答案。有现成正文时仍保留事实，只为预期判断单独裁出有限输入。随后从材料识别三项可观察依据：

- **具体发现**：正文提出了什么判断，靠哪个行为、事实、过程或对照支持。
- **与观众的关系**：哪类观众会关心，哪些已知感受可能被说中，或哪种有依据的预期可能被改变。没有反差就不发明反差。
- **可兑现的收获**：正文实际能让观众理解、辨认或完成什么，以及用什么材料交付。

默认在工作中完成提取，不向用户索取固定格式或展示完整推理。用户要看依据时，用少量原文摘句说明材料映射。自由创作时允许自行构造这些内容，不要求已有真实案例。先确定正文准备兑现的关键答案、解释、方法与步骤，再划定开头的信息范围；不能把防剧透收窄为“不解释原因”。具体区间分工见 [流式接收与表达规则](references/streaming.md)。

## 3. 依方法选择生成动作

方法不同，推进过程也不同：认知冲突需要预期与发现的关系；判断缺口需要评价对象和可解释的标准；奖励预测从真实收获组织承诺；命名精准从具体感受起笔。不能把所有方法都塞进”痛点—反转—承诺”。按选中方法或样本的分支执行。

### 当用户未指定 FS 时

**方式一：使用 Jev 自动选择（推荐）**

脚本需要 Python `requests` 和 `TYPESAFE_API_KEY` 环境变量，且会把正文前 2,000 个字符发送到 TypeSafe AI。运行前说明这项数据传输并取得用户同意；未同意或未配置密钥时，使用下方手动评估流程。不要把 API key 写进仓库或 Skill 文件。

调用 Jev 选择器脚本进行推荐：

```bash
python3 scripts/jev_selector.py <正文文件路径>
```

Jev 会根据正文特征自动提取 15+ 个维度的特征，并返回：
- **推荐的 FS**（FS-001/FS-002/FS-003）
- **置信度**（0-100%，越高越可靠）
- **每个 FS 的匹配度分数**（0-100 分）
- **概率分布**（每个 FS 被选中的概率）

**决策规则**：
- ✅ **置信度 ≥ 80%**：直接使用推荐的 FS
- ⚠️ **置信度 50-80%**：使用推荐的 FS，但可能需要一定改写
- ⚠️ **置信度 < 50%**：所有 FS 匹配度都较低，建议定制开头或选择匹配度相对最高的

**用户强制指定 FS 时**：
```bash
python3 scripts/jev_selector.py <正文文件路径> FS-002
```
Jev 会返回该 FS 的匹配度供参考，匹配度 < 60 分会提示"可能需要较大改写"。

---

**方式二：手动评估（备用）**

当 Jev API 不可用时，从正文提取特征后手动评估每个 FS 的适配概率，核心是判断正文适合用哪个 FS 塑造开头：

**正文特征与 FS 匹配判断**：
```
FS-001（反常归因 → 理解驱动）：
- 正文是否解释”为什么会这样”的机制/原因？
- 正文核心交付是否包含因果解释、机制分析、关键区分？
- 是否存在或可构造”A（正面）→ B（负面）”的反常关系？
- 开头可以用反常关系制造困惑，正文用机制解释完结
- 适合：机制解释型、因果分析型、路径对比型正文

FS-002（形象反差 → 利益驱动）：
- 正文是否揭秘”怎么做到”的具体技巧/方法/步骤？
- 正文是否有可观测成果（粉丝数/收入/播放量）或可编造强度？
- 是否存在或可构造”大成果 + 低门槛 + 简单方法”的价值倒挂？
- 开头可以用反差制造”我也想要”，正文用技巧揭秘完结
- 适合：技巧揭秘型、方法教学型、案例拆解型正文

FS-003（判断缺口 → 自审驱动）：
- 正文是否列举”常见错误/误区/陷阱”？
- 正文结构是否为”N个问题/N种情况/N个误区”的列举型？
- 是否可以让观众产生”我是不是也这样”的自审？
- 开头可以制造判断缺口，正文用列举对照完结
- 适合：误区列举型、问题诊断型、分类对照型正文
```

**关键原则**：
- 最终导向（理解/利益/自审）是开头塑造出来的，不是正文本身就有的
- 判断标准：正文能否支撑开头塑造的这种导向？
- 同一篇正文可能适合多个 FS，选择最容易构造、强度最足的

**输出格式**：
```
推荐：FS-001（用反常归因塑造理解驱动）
概率分布：
  - FS-001: 85%（正文有机制解释，可构造反常关系）
  - FS-002: 10%（正文缺少具体成果数据和操作主体）
  - FS-003: 5%（正文不是列举型结构）
置信度：88%

车厢循环模式匹配度：
  - FS-001: 反常关系建立 → 递进强化 → 承诺例子解释（可构造）✓
  - FS-002: 形象反差 → 价值倒挂 → 技巧承诺（缺少反差元素，难构造）✗
  - FS-003: 判断缺口 → 恐惧点 → 列举承诺（不是列举型，难构造）✗

生成建议：
  - FS-001：正文解释”为什么高深内容反而数据好”，可构造”越通俗越不转发”的反常关系。
    开头塑造理解驱动（”为什么会这样？”），正文用机制解释完结 ✓
  - FS-002：正文缺少”大成果+低门槛+简单方法”元素，即使编造也难达到价值倒挂强度
  - FS-003：正文不是”N个误区”的列举型，不适合塑造自审导向
```

**决策规则**：
- 最高概率 ≥ 70% 且置信度 ≥ 80%：强烈推荐，直接使用
- 最高概率 50-69% 或置信度 60-79%：推荐使用，提示可能需要一定包装
- 最高概率 < 50% 或置信度 < 60%：所有 FS 匹配度都不高，但仍可尝试概率最高的

**重要原则**：
- 短视频开头是吸引工具，不是正文摘要
- 开头和正文可以是松耦合关系
- **模板强度 > 正文事实的严格对应**
- 缺失信息允许编造以达到模板强度
- 概率分布只是推荐，用户可以强制指定任何 FS

### 当用户明确指定 FS 时

直接使用指定的 FS，跳过匹配度评估，进入生成流程。

---

**1. 生成候选表达**（使用选定的 FS）：
- **必须先用 Read 工具完整读取该 FS 文件**（不许凭记忆），提取：母版结构、槽位要求、词性对齐、单句作用、字数范围、原文例句、**车厢循环路径**
- **识别正文表达风格**：读正文前100字，提取表达特征（句长、用词、句式、语气），判断口语化程度
- **检查母版核心要求**（不作为硬性门槛，只作为生成指导）：
  - FS-001：寻找或构造”A（正面条件）→ B（负面结果）”的反常关系，最终导向=理解驱动
  - FS-002：寻找或构造”大成果 + 低门槛 + 简单方法”的价值倒挂，最终导向=利益驱动
  - FS-003：寻找或构造”可自审判断 + 恐惧点 + 列举框架”，最终导向=自审驱动
- 从正文提取可用关系/信息，**按正文风格**生成2-3个候选表达
- **生成时逐句检查车厢循环**：
  - 生成每一句前，先标注”观众到这里已经知道什么”（信息累积）
  - 检查当前句如何**完结旧预期 + 制造新缺口**：
    - 完结了什么预期？（完全/部分/强化）
    - 制造了什么新缺口？（困惑/疑问/期待）
    - 观众是否有理由进入下一句？
  - 例如：第三句要”命名思维”时，必须基于前两句已经建立的”错误做法”来造词，不能凭空命名
  - 每一句的作用 = 前面累积的认知 + 当前句新增信息
- **最后一句必须完成三重作用**：
  - ① 阶段性总结：完结开头累积的所有预期
  - ② 最终导向确立：让观众明确”看完能得到什么”（理解机制/复制成果/纠正错误）
  - ③ 新缺口制造：给观众进入正文的具体理由
- **允许适度包装和编造**：
  - **模板强度 > 正文事实的严格对应**
  - **只有当正文强度不够时才编造**，不是机械套用编造模板
  - 判断标准：正文表达是否已经达到 FS 原文的车厢循环强度？
    - 如果正文说”推荐嘎嘎的””数据好的不得了”，强度已经够 → 不需要编造具体数字
    - 如果正文只说”数据还行””有点效果”，强度不够 → 编造”几十万点赞”以达到强度
  - 编造方向：
    - 增加具体数字（”数据好” → “几十万点赞”）
    - 强化表达（”有点反常” → “完全相反”）
    - 补充缺失信息（正文未提操作主体 → 编造”普通人也能做到”）
  - **底线**：
    - 不能完全脱离正文核心内容
    - 编造必须服务于达到模板强度，不是为了编造而编造
    - 优先使用正文原有表达，只在强度不够时才编造

**2. 防剧透（信息披露边界）**
- 对每个候选表达执行截断前缀预判：观众听到这个表达后，能直接接出什么？
- 正文的关键区分/方法/机制是否被提前透露？
- 检查方法：见 FS-001 第15行剧透判断标准
- 剧透的候选淘汰，保留未剧透的进入下一步

**3. 对齐车厢循环（心理状态切换）**
- 标注原 FS 的车厢循环路径：
  - 每句的【进入理由】→【车厢内旅程】→【车厢末尾状态】
  - 最后一句的【三重作用检查】
- 标注候选表达的车厢循环路径（同样格式）
- 逐句对比：
  - 进入理由是否一致？（同样的缺口类型）
  - 车厢内旅程是否一致？（完结+制造的模式相同）
  - 车厢末尾状态是否一致？（观众是否有同样的理由继续）
- **对齐最终导向**：检查候选表达的最终导向类型（理解/利益/自审）是否与原 FS 一致
- **对齐三重作用**：检查候选表达最后一句是否完成①总结②导向③缺口
- 不一致时调整表达，直到车厢循环路径完全对齐

**执行顺序**：母版要求 → 防剧透 → 对齐车厢循环。每步筛选后才进入下一步。

**核心原则**：车厢循环结构一致性 > 表达差异性。选择最准确的词，即使与原文重复。

详见 [核心术语表 - 生成/重写时的核心要求](references/glossary.md#生成重写时的核心要求)。

---

选用反常识、认知冲突或预测打断时，按 [反常识判断器](references/counterintuitive.md) 的顺序执行：初始预期 → 候选关系与正文交付 → 区间信息分配 → 截断前缀预判 → 选定关系 → 填母版。分别判断关系是否挑战既有认识、开头是否提前暴露正文答案；不能因为观众能接出负面结果就直接判失败。其他方法不强制执行此分支，但仍遵守区间信息分工。

测试时先交付简短候选内容包，再进行前缀探测和选择，最后才写完整开头；保留阶段输出，不能用成稿后补写的底稿证明步骤已执行。独立上下文可用且已获授权时，预期窗口只接收受众、题材或截止当前的前缀，不接收正文解释；单窗口运行只能称受限视角估计。正常使用不要求用户逐阶段确认或查看工作表。

指定 few-shot 时，按该条母版的句式骨架、表达段顺序及篇幅生成，不得降级成仅借用心理机制。FS-001 保留”困境的关键原因就是……，甚至……越……，……就越……。解释性追问＋小投入与明确收获”，以原文 72 字为目标，具体分配和允许替换范围见样本。材料不匹配时调整材料选择或说明缺口，不能编造因果或静默放宽骨架。

用户要求同一正文两版时，保持事实和中心；指定母版时只在其允许范围内调整对象措辞和内容槽位，不改变开场顺序。用户说“随便写两条”且没有正文时，可自选不同题材，不额外限定必须同一底稿或日常生活技巧。

## 4. 按流式接收顺序组织表达

每个片段只使用此刻应该出现的信息，明确它承接前文的何种状态。优先沿用材料中的具体对象、动作、结果，逐步建立关联、期待和交付；不要先写一段抽象分析，再压成口播。

按区间分工生成：好奇区间用现象、素材、反差和待解释的判断建立问题；引子收束悬念并承诺收获；正文交付关键答案、解释与方法。FS-001 的反常归因和递进结果用于建立待解释的关系，追问与承诺用于引出正文；这些槽位都不能提前交付本篇正文的核心内容。是否剧透要对照本篇准备兑现什么，不能只看有无因果句或某个词。

一个词可以同时圈人、建立价值和留下答复期待。用词与词、词与句、句与句的组合生成作用，不逐字机械填表。分析者的解释不等于观众的内心独白。

称呼、内容和结果承诺的措辞可以按槽位替换，句式变化以当前样本明确允许的范围为限。按样本给定的篇幅及信息类型分配直接组织；不能通过缩短表达、改成暗示或换同义词，把正文核心交付提前塞进开头，也不能为降低理解负担而抢先回答本应保留的核心问题。用户给定的逗号断句与 `/` 停顿逐字保留；没有依据时不替作者添加所谓原始停顿。

## 5. 接入正文并交付

从正文中选定实际承接句，处理开头与原第一段的重复。默认给“从哪句接入／替换哪一段”的简短定位；必要时附一条过渡，不擅自改写整篇正文。

交付：用户指定数量的开头；没有指定时两条。推荐与接入说明合计保持简短。用户只要开头时省略额外说明，但开头本身仍需可接入正文。

事实、因果和可兑现的承诺应在材料选择与生成时就成立，不能先保留制造虚假反转的规则，再依赖一轮质检补救。完成当前开头任务即结束，不自动安装、发布、写文件或进入下一阶段。

## 验证边界

本框架只声明实际通过的结构检查。是否写得好、迁移是否成立、观众是否愿意继续听，需要另外验证。独立窗口测试说明放在 `evals/handoff.md`；除非用户要求测试组织或维护，不读取该文件。
