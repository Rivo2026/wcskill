# 学习流程：根据实际理解改变下一轮

本流程既处理一个关键概念的针对性讲解，也处理连续课题。目标是帮助使用者形成可解释、可迁移的理解。每轮只推进当前需要的知识单元。

## 1．确定起点和依赖

从直接学习主题、研究中暴露的缺口或已认可的知识地图进入。继承原问题、目标、证据与边界，不能重新从零问一遍。

圆桌中出现知识缺口时，可由最相关的一个角色或主持人讲解，暂存其他人的立场与争议。用户只要把概念弄懂时不让全体重复讲课；问题重新涉及不同解释时，按 [圆桌运行](roundtable.md) 回到原组讨论。不要因为插入一段教学就丢失圆桌状态。

新课题需要判断已有基础。用户说从零开始，就按从零设计；用户限定“只用这些材料”时遵守范围，只给出起点材料时先读它，再按任务需要补充并说明来源；用户要求结合项目时，按必要索引定位少量相关材料。未指定时优先使用当前对话，只有起点差异会显著改变教学才询问。

判断基础的证据强弱：

- 用户确认掌握，或在实际回答中正确解释、应用：可作为依据。
- 用户采用过的正式材料：可能代表接触或理解，结合当前表达判断。
- AI 草稿、第三方文章、收藏或文件中出现过的词：只能证明材料存在。

可用一句简单的应用提问了解起点，但不为了显得严谨先做整套考试。没有证据时透明地按暂定起点开始。

连续学习计划记录：学完希望能判断或完成什么、必要知识依赖、可选扩展和当前起点。先安排足以进入第一轮的路径；后续可以被反馈调整。

## 2．开始下一轮前读取反馈

继续课题时，按 [课题记录](records.md) 读取当前状态、上一轮实际讲解和用户真实反馈，再决定主题。不能只看最大文件序号就生成下一篇。

反馈包括用户原话、自己举的例子、应用回答、练习或实践结果。忽略模板问题、未填写区域、系统生成的总结和预告。

如果没有反馈：用户没有要求继续时，可以提出一个与当前缺口有关的轻量问题；用户已经明确要求继续或跳过检查时，按当前基础推进，并将掌握状态保留为未验证。不得反复阻拦同一继续请求。

## 3．组织本轮讲解

本轮的知识单元需要包含以下教学动作，顺序和篇幅随内容调整：

1. **进入具体问题**：从原问题、可观察现象或真实疑问开始。使用者没有表达误解时，直接讲解，不编造“你一直以为”。
2. **搭接已有知识**：找到已经理解的经验或概念，说明新概念新增了什么区别。
3. **解释形成过程**：讲清它原本解决什么麻烦、关键因素怎样作用、为什么会产生结果。术语随解释出现。
4. **把一个例子跑完**：交代初始条件、过程、结果，以及各部分怎样对应概念。教学假设标明为假设，不冒充真实案例。
5. **改变条件**：替换一个关键条件，观察结论是否仍成立，用来显露适用边界和竞争解释。
6. **回到原问题**：说明掌握它以后，哪些理解、选择或行动会变化；仍有争议时保留争议。

用连续段落解释因果，表格和图用于呈现关系。类比帮助理解，不能作为理论成立的证据。不给每课规定相同字数，也不为了凑结构引入无关概念。

## 4．通过新情境检查理解

连续陪学通常在本轮末尾给一个简短的解释或迁移问题。关键概念可同时检查：能否用自己的话讲清、能否在条件变化的新情境中应用。

在用户回答前不把示范答案紧接着展示成“检查结果”。用户只要说明、答案或连续阅读时尊重其选择；可以提供自查问题和解答，但不据此宣称掌握。

检查针对当前能力，不考未讲过的外围知识。答案不采用固定措辞，只要机制、条件和推论成立就可以通过。语言表达不流利不自动意味着概念不懂。

## 5．反馈决定下一步

| 实际证据 | 下一轮动作 | 状态记录 |
| --- | --- | --- |
| 能准确解释并迁移到新条件 | 进入下一个依赖已满足的知识点 | 记录回答依据与已展示能力 |
| 主机制正确，局部条件遗漏 | 指出具体偏差，短补充；不影响下一步时继续 | 记录已理解部分及仍需留意的条件 |
| 核心概念混淆，推论失效 | 留在当前节点，换例子或拆回必要基础 | 记录具体混淆，不升级为掌握 |
| 不知道或暂时说不清 | 从已知经验重新搭接，降低抽象度 | 暂未判断，不贴能力标签 |
| 理解了，但想知道怎么用 | 转入用户场景的应用比较或小尝试 | 将应用目标接回原课题 |
| 感到无关或不想沿原路线 | 调整学习目标或切入角度，明确保留的原问题 | 记录用户选择，不视为理解不足 |
| 只有“收到”、空反馈或明确跳过 | 按明确的继续意图推进，或等待 | 掌握未验证 |
| 回答提出有效反例或新证据 | 重新研究原解释，必要时修订讲解 | 记录结论变化及依据，不强行判错 |

同一问题换过解释仍未解决时，回查前置知识、例子和原解释是否有问题，再决定怎么调整，不无限重复同一说法。

## 6．把理解接到真实验证

涉及实践方法时，与使用者明确一个可行的尝试：当下条件、预期变化、观察指标和失败信号。只有实际执行并回填的结果才进入实践记录。

得到结果后依次检查：原先条件是否成立、执行是否发生、结果测量是否可靠、是否有其他解释。失败可能来自方法边界或原判断错误，不能统一归为学员没有学会。

使用者希望公开分享时，可以整理本次学到的判断、来源、实践结果和局限。没有亲自做过的部分保持知识解释或候选方法身份。

## 7．记录并停下

本轮讲解结束后停下来接收反馈，不替用户填写答案。已授权建立或更新连续课题时，同步本轮内容、实际反馈、当前状态与待恢复位置；记录方法见 [课题记录](records.md)。

教学内容已生成只表示已讲解；真实反馈已收到才表示已反馈；理解检查有证据才表示已展示掌握；实际应用回填才表示已有实践结果。这几个状态不能相互替代。
