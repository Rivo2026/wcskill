# 圆桌运行：独立研究、交叉回应、主持人审议

## 会话入口

1. **已有活动圆桌**：恢复议题、已确定的人物、各人上一轮立场、未决分歧及主持结论。普通追问和补充交给同组人，不能每轮重新选人。
2. **已指定人选**：按指定名单启动；缺少议题时只补议题。用户说“你来选，直接开始”等已授权代选时，说明选择后立即研究。
3. **首次研究且未确定人选**：先按本文件选人，展示每人的框架、负责变量和入选理由，合并让用户确认或调整一次。仅讨论工具设计不等于已经启动圆桌。
4. **只问释义、只要结论或要求单人讲解**：按指定深度回答。圆桌里插入知识讲解时暂存名单和争议点，不擅自关闭原讨论。
5. **退出或换任务**：明确“结束圆桌／结束讨论”、要求回到主助手、转向不相容的新任务或调用其他工具时结束或暂停圆桌，服从新任务。用户要求单次圆桌报告时，交付后结束；持续圆桌本轮完成后保持活动并等待输入。

## 选人依据与分工

先把问题拆成值得研究的变量，再找代表不同方法的人物。人物库覆盖西方社会学、哲学、传播学、心理学及消费研究；默认选 3–5 位，范围窄时可减少，用户指定人数时照做。跨领域问题通常取社会关系、概念与价值、媒介与受众、判断与消费中的互补角色，不按领域凑席位。

每个入选者都要有：有出处的核心框架、对原问题的具体追问、其他人未覆盖的变量、解释边界。只因有名而加入的人淘汰；不会给所有角色同一套问题再换名字。推荐记录一句“为什么这次需要他”，可以说明另一候选为何暂不加入。

[人物与方法](thinkers.md) 是候选库，用户可以点名库外人物。库外人选先核实可用于当前问题的方法和材料；不能只凭名言或人格印象生成角色。理论的流行、人物声望或生死都不决定证据强弱。

## 一轮怎样运转

### 1．主持人制作共同问题包

所有角色收到相同的用户原话、本轮焦点、已知事实、待核实材料、目标与范围、来源及访问状态；同时收到自己的方法卡、研究职责和必要的 [研究流程](research.md)、[来源与结论](evidence.md) 规则。

首轮不提供主持人的预设答案或其他角色的开场结论。续轮必须提供上一轮各人最终立场、真实争议、主持结论及新增材料。将原始事实与上一轮分析分开，避免把讨论推论回填成事实。

### 2．每个角色独立研究

完整运行时，每位人物使用一个独立子代理，按客户端可用并发数分批启动。首轮分批的角色仍不读其他人的开场，保证分析独立。继承当前工具、模型设置和权限，不硬编码模型，不创建用户可见的新任务，不让角色自行再分裂代理。

若工具默认复制主会话，首次创建角色时显式改为最小隔离上下文（例如支持时使用 `fork_turns: none`），只传共同问题包及该角色方法。这里的独立是首轮输入与判断分开；不代表多个代理拥有独立的外部事实或来自不同模型。

每位角色返回：

- 自己认为真正需要解释的现象，必要时质疑原前提；
- 一项主要解释及形成它的具体依据、必要条件；
- 对当前材料的对应分析，哪些只是框架应用或候选假设；
- 最可能让自己改变判断的证据，以及需要其他视角补足的盲区。

研究可深入，面向用户的开场通常约 200–350 字，围绕一项实质判断。需要更长证据说明时单列依据，不靠戏剧台词、人物口头禅或术语堆叠增加篇幅。

### 3．主持人找出可以交锋的判断

读全部独立结果后，提取会改变答案的少量分歧，标出“谁的哪个判断”和“另一解释差在哪里”：

- 对事实理解不同：需要核实资料；
- 机制或因果解释不同：需要区分条件、预测或案例；
- 概念用法不同：先澄清各自所指；
- 价值取舍不同：说明各自优先什么，不能伪装成事实已经裁决；
- 分析层次不同：可能互补，检查怎样相互作用，不强判为冲突。

为便于跨轮追踪，可给关键判断和分歧简短编号。每位角色至少拿到一条与其判断相关的质询或补充；没有实质冲突时，要求回应另一人补入的条件或共同盲区，不制造争吵。

### 4．角色阅读彼此意见并回应

使用原角色代理的后续消息，发送目标判断的原话及位置，保留限定条件和证据身份，再附对方的质询与依据。待验证预测、候选观察不能在交接时变成已作出的结论或已经发生的事实。区分对方在反驳现有主张，还是补入边界。

角色需先准确复述对方的主张，再回应依据。涉及自己的判断变化时，对照实际原话说明属于保留、补充证据、细化边界，还是撤回某项主张。只有原先确实作出的判断才可撤回；原文已有的限定不能写成这一轮才纠正的错误。没有改变也可以带来更具体的解释或验证办法。

不同问题可以并行回应；某个回应依赖另一人刚提出的新论点时顺序发送。被质疑者必须获得回应机会，不能主持人代替他认错，也不能让最后发言者未经回应就胜出。分歧没有新证据时保留未决，不无限循环；一轮通常完成一次独立研究和一次相互回应，必要时补一次决定性回应。

### 5．核对会改变结论的证据

主持人或负责该判断的角色，按研究流程核对原始理论、案例、反例和当代资料。不是所有引文都重新检索，只处理结论依赖的关键依据和争议来源；共享已核实的出处及其可支持范围。

外部证据改变某人判断时把它交回该角色修订，保留修改前后的差异。角色之间相互同意、同一模型多次回答相似、不同链接转载同一材料，都不能当作独立证据。

### 6．主持人审议并交付

主持人独立判断，不按人数、知名度、台词气势或折中平均裁决。交代：

- 本轮实际增添了什么认识，哪项直觉被推进或修正；
- 哪些结论已有依据，哪项分歧只是概念或层次差异，哪项仍是真正冲突；
- 谁改变了哪一项判断、为什么：用实际前后发言建立变化记录，不能仅凭角色自述“我之前认为／现在撤回”；已有边界、新增证据和真正撤回分开记录；
- 人物都忽略了什么，以及目前证据能支持的条件性答案；
- 下次最值得追问或验证的一点。只有用户需要行动时才给具体尝试。

常规输出是“本轮议题与阵容 → 各人的主要判断 → 实质交锋 → 主持人审议”。续轮省去已知介绍。来源跟随判断，发言标明“姓名｜框架”，开场的模拟说明不必每段重复。

## 可复用的角色任务格式

```text
以 {人物} 已发表的 {框架} 为依据，模拟一个研究角色；不冒充本人，不编造原话。
原问题：{用户原话}
本轮焦点：{当前问题}
共同事实与材料：{材料、出处、访问状态；分析推论另列}
此前状态：{续轮各人最终立场、分歧、主持结论；首轮省略}
你负责的变量：{具体分工}
方法：{从人物卡选择与当前问题有关的分析动作}
本次阶段：{独立研究／回应某人的具体判断／根据新证据修订}
需要回应的内容：{仅后两阶段提供，含目标原话及位置、原有限定、证据身份、具体质询与依据}
返回：主要判断、依据与条件、对原问题的应用、盲区；回应阶段将实际原判断与当前判断对照，说明保留、补证、边界细化或撤回的依据。
区分原著观点、当代框架应用与已核实事实；材料不足时保留未知。
只读取本问题必要材料，不写课题文件、不发布、不付费、不再创建代理。
```

## 状态与能力边界

每轮保留：议题、名单及分工、角色当前立场、关键证据状态、未决分歧、主持结论、用户新反馈、停止位置。长对话压缩早期内容时保留修订链和来源位置；不能把未决压成共识。文件保存遵循 [课题记录](records.md)，代理运行 ID 只是当前会话句柄，跨会话恢复依赖内容记录。

当前环境允许且提供多代理工具时按上述方式执行。可用并发数少于人数时分批；代理不可恢复时用原角色状态重建，明确其为恢复调用。某角色失败时报告缺席，可在允许范围内重试一次或展示已完成的部分，不能编造其发言。

环境不提供或不允许多代理时，先明确说明独立角色能力不可用；可提供单助手多视角模拟，并标为降级执行，不声称独立代理已经讨论。用户明确要求独立代理时，不能静默降级。无论执行方式如何，模拟人物都不构成外部专家背书。
