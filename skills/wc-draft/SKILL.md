# wc-draft

## 核心目标

把用户的观点和材料，通过"接收材料 → 询问是否对标作者 → 分析材料 → 匹配框架 → 给方案 → 确认 → 写稿"的流程，写成完整的口播文案正文。

**输入**：
- 用户提供的材料（观点、例证、数据、故事等）
- 可选：指定作者 + 该作者的文案文件

**输出**：
- 完整的口播文案正文
- 或结构化写作方案（如果用户只要方案）

**服务赛道**：知识讲解、知识付费、知识博主

---

## 八大元素

在规划段落时，需要明确每段使用哪些元素。元素只能从以下八种中选择：

1. **关键词**：核心概念、专业术语或人物名称，用于标记主题、定位领域、建立认知锚点

2. **钩子**：制造注意力和停留的元素，包括但不限于反差、反常识、冲突、悬念、信息缺口、造词、金钱数字、价值承诺等能让观众产生"想看下去"的刺激点

3. **观点**：明确的判断、结论或主张，表达作者对某个问题的立场

4. **例证**：支撑观点的具体证据，包括案例、故事、数据或事实

5. **方法**：可执行的操作步骤、技巧或解决方案

6. **秀肌肉**：展示作者或其团队的实力、成绩、资源、操盘能力的信息，用于建立信任和权威

7. **商业目的**：与商业转化相关的内容，包括但不限于建立商业价值感知、团队背书、引流话术、身份标签、签名档等，可以是显性的也可以是隐晦的

8. **引导互动**：引导观众做出具体行为的话术，包括评论、点赞、关注、私信等

**重要**：在给方案时，"元素组合"或"固定元素"只能从这八个元素中选择，不得自行发明新元素（如"靶子"、"劈定义"、"快速转折"等）。

## 阶段1：接收材料

收到用户材料后，先询问：

```markdown
收到材料。

请问是否需要对标某位作者的风格？

- 如果有，请提供该作者的文案文件（CSV或断行版MD），我会分析后提取系列框架
- 如果没有，我会用通用框架来规划
```

**用户可能的回复**：
- "对标XX" + 提供文件路径 → 进入作者模式
- "如果是XX会怎么写" + 提供文件路径 → 进入作者模式
- "没有" / "不用" / "直接写" → 进入通用模式
- 直接说"开始" / "可以" → 进入通用模式

---

## 阶段2：深度分析用户材料

**通用模式和作者模式都需要先分析用户材料**

判断材料的充分程度（内部处理，不展示给用户）：

### 情况A：材料充分
- 观点清晰、论据完整、例子充足
- 只需要重新组织顺序和推进方式
- → 框架匹配以"保留所有内容"为前提

### 情况B：材料溢出或不完整
- 观点过多，无法在一篇文案中展开
- 或有观点但缺例证/数据
- → 允许删减观点或标记"需要补充"

### 材料结构特征

逐个检查：
- 是否有真实案例/人物故事？
- 是否有明确的分类维度？
- 是否有颠覆性观点 + 可拆解的隐含前提？
- 是否有明确的问题 + 解决方案？
- 是否有误区 vs 正确做法的对比？
- 是否有分层逻辑（表象-深层-本质）？
- 是否有A vs B的对比？
- 是否有有趣的现象 + 背后规律？
- 是否有多个案例 + 行业趋势？

### 内容目标

识别文案要达成什么目标：
- 建立信任？
- 输出方法？
- 破除认知？
- 分析趋势？
- 深度论证？

## 阶段3：匹配框架

### 通用模式（没有指定作者）

从10个通用框架中自动匹配最适合的。

#### 10个通用框架

1. **问题-方案（直接型）**
   - 定义：提出问题 → 直接给方案（可能分步骤），弱化或跳过原因分析
   - 适用：观众已认同问题，只需要方案；原因分析不重要

2. **问题-原因-方案（分析型）**
   - 定义：提出问题 → 深入分析原因 → 给针对性方案
   - 适用：原因分析能增强说服力；需要因果逻辑

3. **故事+观点**
   - 定义：故事引入 → 故事展开 → 数据/结果 → 提炼观点/方法
   - 适用：有真实案例，需要建立信任

4. **分类展开**
   - 定义：提出分类框架 → 逐个展开 → 总结/选择建议
   - 适用：有明确分类维度，需要系统讲解

5. **拆解隐含前提**
   - 定义：提出大众观点 → 指出隐含前提 → 拆解前提 → 给出新框架
   - 适用：有颠覆性观点，破除大众认知

6. **误区纠正**
   - 定义：指出误区 → 分析来源 → 给正确理解 → 给正确做法
   - 适用：有明确的错误vs正确对比

7. **递进论证**
   - 定义：表象层 → 深层逻辑 → 本质层 → 应用层
   - 适用：有分层逻辑，需要层层递进

8. **对比论证**
   - 定义：提出对比 → 展开A → 展开B → 解释机制/给建议
   - 适用：有A vs B对比

9. **现象-机制-应用**
   - 定义：提出现象 → 拆解机制 → 如何应用
   - 适用：有有趣现象，需要提炼规律

10. **趋势分析型**
    - 定义：现象归纳 → 趋势判断 → 机会指向
    - 适用：有多个案例，分析趋势

#### 匹配决策树

按以下顺序检查，第一个匹配成功就停止：

1. 材料中有真实案例/人物？ → **故事+观点**
2. 材料中有明确分类维度？ → **分类展开**
3. 材料中有颠覆性观点 + 隐含前提可拆？ → **拆解隐含前提**
4. 材料中有明确问题 + 解决方案？
   - 原因分析重要？ → **问题-原因-方案**
   - 原因分析不重要？ → **问题-方案**
5. 材料中有误区 vs 正确做法？ → **误区纠正**
6. 材料中有分层逻辑（表象-深层-本质）？ → **递进论证**
7. 材料中有A vs B对比？ → **对比论证**
8. 材料中有有趣现象 + 背后规律？ → **现象-机制-应用**
9. 材料中有多个案例 + 行业趋势？ → **趋势分析型**
10. 都不匹配？ → 提示用户补充材料或明确需求

**重要**：必须通过深度理解材料的逻辑结构来匹配框架，不能只用关键词匹配。

### 作者模式（指定了作者）

流程：

```
步骤1：读取并分析作者文案文件
  ↓
步骤2：提取作者系列框架
  ↓
步骤3：判断用户材料属于哪个系列
  ↓
步骤4：应用该系列的框架结构
```

#### 步骤1：读取并分析作者文案文件

读取用户提供的作者文案文件（CSV或断行版MD）。

**需要识别的信息**：
- 该作者有哪些高频出现的系列框架
- 每个系列的结构特征
- 每个系列的使用频率

#### 步骤2：提取作者系列框架

**提取目标**：识别出该作者的3-5个高频系列，并为每个系列提取**可机械执行的写作公式**

**提取方法**：

1. **识别系列的步骤**：
   - 深度阅读该作者的多条文案（建议至少10-15条）
   - 识别出重复出现的结构模式
   - 聚类分析：哪些文案的结构是相似的
   - 统计每个系列的使用频率

2. **为每个系列提取以下信息**：

   **系列名称**：
   - 简短命名，反映该系列的核心特征
   - 例如："学员案例系列"、"流量拆解系列"、"破除认知系列"

   **识别特征**：
   - 什么样的材料/观点属于这个系列
   - 判断标准（关键词、材料类型、观点类型）
   - 例如：包含"学员"、"成功案例"、"月入X万"等关键词，材料类型是真实案例，观点类型是建立信任

   **段落结构**：
   - 该系列通常分几段
   - 每段的具体作用（不能用"开头/中间/结尾"，要写具体作用）
   - 例如：
     - 段落1：引入人物（学员背景+困境）
     - 段落2：转折点（遇到作者/加入课程）
     - 段落3：秀数据（具体成绩+时间线）
     - 段落4：提炼方法（成功的关键）
     - 段落5：引流（如果你也想...）

   **固定元素**：
   - 每段使用哪些八大元素
   - 只能从八大元素中选择
   - 例如：段落1用"关键词+钩子+观点"，段落3用"例证+秀肌肉"

   **推进方式**：
   - 段落间如何连接
   - 信息密度（高/中/低）
   - 推进节奏（快速转折 / 深度展开 / 逐步递进）
   - 例如：快速推进，信息密度高，用反问连接

   **收束方式**：
   - 每段末尾的车厢循环逻辑
   - 如何制造未闭合 + 新缺口
   - 例如：段1末尾提"然后他做了3件事"（制造缺口），段2展开第1件事

   **写作公式**（重要！必须提取）：
   
   这是最关键的部分，要提取**可机械套用的公式**，而不是描述性特征。
   
   - **开头公式**：
     - 公式A：[具体模板]
       - 示例：[从真实文案摘取]
       - 适用场景：[什么情况用这个公式]
     - 公式B：[具体模板]
       - 示例：[从真实文案摘取]
       - 适用场景：[什么情况用这个公式]
   
   - **论证公式**：
     - 公式A：[具体步骤]
       - 示例：[从真实文案摘取关键句式]
       - 例如："这背后有X个隐含前提" → 拆解前提 → "换句话说..."
     - 公式B：[具体步骤]
       - 示例：[从真实文案摘取关键句式]
   
   - **举例公式**：
     - 举例顺序：[从哪里到哪里]
       - 示例："很多人..."（泛指）→"你像XX"（具体案例）→"我自己"（亲身经历）
     - 例子数量：一个观点通常举X个例子
     - 连接词：用"包括""然后""你像""比如"等
   
   - **收尾公式**：
     - 公式A：[具体结构]
       - 示例：[从真实文案摘取]
     - 公式B：[具体结构]
       - 示例：[从真实文案摘取]

   **文风特征**：
   - 口语化程度（高/中/低）
   - 口语填充词习惯（常用哪些填充词，如"啊"、"对吧"、"嘛"、"呢"、"吧"、"其实"、"恰恰就是"、"这个词儿"、"完全没有任何必要"，以及使用频率）
   - 句式特点（短句/长句倾向，是否常用"就是"、"你像"、"那这个时候"、"那么换句话来说"等开头）
   - 絮叨/简洁倾向（同一个意思是否反复说、绕着说、用不同方式重复强调同一个点）
   - 自我指涉频率（是否常说"我前面讲过"、"我之前视频说过"、"包括我自己也是"、"我最近的感悟"、"我经常说一个东西叫做"）
   - 过渡词使用（如"那么换句话来说"、"所以我们就会发现"、"那这就导致了一个现象"、"更要命的是"）
   - 推进线性度（是线性推进，还是会岔开话题再绕回来）
   - 举例密度（一个观点通常举几个例子，如何连接）
   - 典型口头禅或标志性表达

   **典型案例**：
   - 从该作者的真实文案中摘取2-3个该系列的完整案例
   - 标注该系列的使用率（例如：25%的文案使用该系列）

3. **公式验证**（必须执行）：

   提取完公式后，必须用公式反向匹配3-5条真实文案，验证公式的准确性：
   
   - 开头是否符合提取的公式A或B？
   - 论证是否用了提取的论证公式？
   - 举例是否符合提取的举例公式（顺序、数量、连接词）？
   - 收尾是否符合提取的收尾公式？
   
   如果匹配度低于80%，说明公式提取错了，需要重新提取。

4. **输出格式**：

   在内部形成如下结构（不需要输出给用户，仅供后续步骤使用）：

   ```
   作者：[作者名]
   
   系列1：
   - 系列名称：[名称]
   - 识别特征：[特征]
   - 段落结构：[结构]
   - 固定元素：[元素]
   - 推进方式：[方式]
   - 收束方式：[方式]
   - 写作公式：
     - 开头公式：[公式A/公式B及示例]
     - 论证公式：[公式A/公式B及示例]
     - 举例公式：[顺序、数量、连接词]
     - 收尾公式：[公式A/公式B及示例]
   - 文风特征：[详细特征]
   - 典型案例：[2-3个案例]
   - 使用率：[百分比]
   - 公式验证：已验证X条文案，匹配度Y%
   
   系列2：
   - ...
   
   系列3：
   - ...
   ```

#### 步骤3：判断用户材料属于哪个系列

根据提取的系列框架的"识别特征"，判断用户的材料/观点属于哪个系列。

**判断逻辑**：
1. **关键词匹配**：材料中是否包含系列的关键词
2. **材料类型匹配**：材料是"成功案例"还是"爆款拆解"还是"老板建议"
3. **观点类型匹配**：用户的观点属于"建立信任"还是"输出方法"还是"破除认知"

计算匹配分数：
```
匹配分数 = 关键词匹配度 × 0.4 + 材料类型匹配度 × 0.4 + 观点类型匹配度 × 0.2
```

选择分数最高的系列。

如果所有系列分数都低于50%，判断为"不属于任何系列"，提示用户：

```markdown
根据分析，该作者的文案主要分为以下系列：
- 系列1：[系列名]（使用率X%）
- 系列2：[系列名]（使用率X%）
- 系列3：[系列名]（使用率X%）

但你的材料不太符合这些系列的特征。

建议：
- 方案A：调整材料，使其更符合某个系列（例如补充[具体内容]）
- 方案B：用通用框架来规划

你希望怎么做？
```

#### 步骤4：应用该系列的框架结构

读取该系列的：
- 段落结构（每段的作用）
- 固定元素（每段必有的元素）
- 推进方式（快/慢，密度高/低）
- 收束方式（段落间如何连接）

### 模糊的信号（不算确认）

- "嗯"

### 支持的调整类型

- → 按新框架/系列重新规划，输出新方案，再次等待确认

- 用户说："第2段和第3段换一下" / "删掉第4段" / "多加一段XX"

## 阶段6：写稿

### 写稿原则

**1. 严格按方案写**
- 每段的内容来源、车厢循环、元素组合都按方案执行
- 不自己加戏，不偏离方案
- **作者模式特别注意**：严格套用方案中指定的写作公式（开头公式、论证公式、举例公式、收尾公式），不能用自己的方式写

**2. 用口播语态**
- 像一个人在面前说话
- 不是演讲稿、不是书面文章、不是PPT大纲

**3. 控制注意力负载**
- 每段只有一个主要疑问
- 不能同时有多个悬而未决的疑问

**4. 气口断行**
- 一行一拍，行尾是信息缺口
- 每行结束在自然的停顿处

**5. 意群分段**
- 在不同意群之间加标题【意群大意】
- 例如：【开局否定】【学员现象】【具体表现】【举例说明】【机制命名】等
- 标题用粗体，放在该意群的开头
- 意群的划分依据段落结构（每个"段落X：具体作用"就是一个意群）

### 表达规则

#### 口播语态

**是什么**：
- 像一个人在面前跟你说话
- 对象感 + 口播感
- 有人味，不是机器生成的感觉

**具体做法**：

1. **用口语化表达**
   - ✓ "你可能也遇到过"（口语）
   - ❌ "您或许也曾遭遇过"（书面）

2. **用短句**
   - ✓ "他做了3件事。第一件，找合伙人。"
   - ❌ "他做了3件事，第一件是找合伙人，第二件是..."

3. **用具体词，不用抽象词**
   - ✓ "月入10万"（具体）
   - ❌ "获得了可观的收入"（抽象）

4. **用"你"，不用"大家" / "各位"**
   - ✓ "你看完这个视频就知道了"
   - ❌ "大家看完这个视频就知道了"

5. **适度保留口语停顿词**
   - ✓ "这个事儿吧，其实很简单"
   - ✓ "但是，问题来了"
   - ❌ 过度使用"那么""然后""就是说"

6. **用反问、设问**
   - ✓ "为什么会这样？"
   - ✓ "你猜结果怎么样？"

7. **避免文艺腔、鸡汤腔**
   - ❌ "在人生的道路上"
   - ❌ "成功的花，人们只惊羡她现时的明艳"

#### 气口断行

**一行一拍，行尾是信息缺口**

**例子**：

✓ 好的断行：
```
很多人以为做一人公司
就是一个人干所有事

但这有个隐含前提
一人公司等于没有外部协作

真相是
一人公司不是一个人干所有事
而是一个人做决策
```

❌ 不好的断行：
```
很多人以为做一人公司就是一个人干所有事，但这有个隐含前提，一人公司等于没有外部协作。真相是，一人公司不是一个人干所有事，而是一个人做决策。
```

**断行原则**：
- 每行结束在自然的停顿处
- 行尾是信息缺口（制造"然后呢"的感觉）
- 便于口播者把握节奏

### 车厢循环的核心逻辑

**内容单元推进 = 制造未闭合 → 部分收束 → 立刻制造新未闭合**

**不是**：
- ❌ 未闭合 → 完全闭合（观众会划走）
- ❌ 同时制造多个未闭合（注意力超载）

**而是**：
- ✓ 前一个疑问被部分收束（变成一个具象对象）
- ✓ 但这个对象是什么、怎么用，仍然未闭合
- ✓ 立刻引向下一段

**注意力负载控制**：
- 同一时刻只有一个主要疑问
- 可以加重一个疑问，不能并列多个疑问

### 写完后

- 直接输出文案
- 不需要总结"我按方案写完了"
- 不需要加"希望对您有帮助"之类的客套话

**输出格式要求**：
- 每个意群之间用标题【意群大意】分隔
- 标题用粗体，例如：**【开局否定】**
- 标题下直接是该意群的文案内容（气口断行）
- 意群的划分依据方案中的段落结构

**示例格式**：
```
**【开局否定】**

如果你已经用上了这个世界上最先进的AI
并且以此为乐
那么大概率你正在利用AI加重自己的拖延症

**【学员现象】**

这个其实会存在一个很大的问题
就是最近我发现很多学员
他们学完线下课之后
开始什么都想要让AI去完成
```

## 追问策略

### 何时追问

1. 材料信息不足 → 追问具体内容
2. 内容目标不明确 → 追问希望达成的效果
3. 用户反馈模糊 → 追问是否确认

### 追问原则

**1. 问题具体，不空泛**

❌ 不好的追问：
```

```

✓ 好的追问：
```
请问这篇文案的主要目标是：
A. 引流（吸引观众私信/报名）
B. 输出方法（让观众学会具体做法）
C. 破除认知（让观众反思自己的误区）
```

**2. 给出选项，不让用户从零思考**

**3. 一次最多问1-2个问题**
