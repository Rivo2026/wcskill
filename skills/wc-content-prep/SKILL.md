# 内容共创

wcskill 系列的内容准备阶段。调用名：`$wc-content-prep`。

把立意、语音碎片、初稿、经历或一篇、多篇同行文案，整理成下一阶段可以据此写作的内容准备结果。用户可以只提供同行原文，不必预先拆解或已有观点。既整理用户已经有的判断，也通过讨论帮助用户形成自己的判断。

本 Skill 自带所需方法，不调用或依赖 dbs。只处理四阶段流程中的内容准备。

## 核心要求

- 一篇围绕一个中心；内容目的可以是理解、学习、改变判断、行动或购买，不默认卖货。
- 区分选题（讨论的问题）、观点（作者的判断）、论据（支持判断的依据）、话题（受众关心的更大问题）。
- 用户事实、已确认立场、同行主张、外部证据和 AI 建议分别标明。用户或同行说过，不等于已证实。
- 允许明确反对、批评或比较同行观点。判断强度由证据决定，不自动软化为“各有道理”，也不为制造冲突扩大对方的主张。
- “正确”和“非共识”分开检验。证据只够支持一个候选时就称候选；与几个同行不同，不能据此宣布整个行业都错了。
- 同样审查用户和 AI 自己的判断。发现反证要说明，不能为用户找辩护材料而隐去反证；改变已确认立场前要让用户知道。
- 提炼观点要能改变一个具体判断、解释或选择。反义改写、词语升级、空泛的“看情况”，不算完成差异化。
- 不虚构经历、对话、数据或观众心理，不搬用同行身份。示意例子只能解释，不能作为现实证据。
- 利用同一窗口已有信息；独立交接时保留关键材料本身和边界，不只写“见上文”。
- 分析所需信息与用户需要看到的结果分开。同行观点、分论点、论证路径、结构和案例编排默认不展示；不能仅换成问句或“我们的候选”便提前输出。

## 按当前状态推进

| 当前输入 | 处理方式 |
| --- | --- |
| 已有观点、素材或初稿 | 整理并检验，不强制加入同行对照或反对意见。 |
| 只有一篇或多篇同行文案，用户尚无自己的判断 | 读取 [同行对照与观点提炼](references/peer-differentiation.md)，先展示话题、开放问题和关键事实或现象，进入讨论；暂不输出同行观点或替用户定结论。 |
| 已有自己的判断，希望找差异或批评同行 | 读取同一参考，围绕已有判断检验与对照；必要时展示相关主张和原文，不重复要求用户先独立思考。 |
| 想找差异化但没有同行内容 | 先用已有经历形成判断候选；必要时邀请补充同行选题、原话或正文。缺少比较依据时不声称已经找到行业非共识。 |
| 材料很少，立场尚不明确 | 给出有材料依据的建议主线，或问会改变主线的关键问题；不假装作者已同意。 |
| 用户只要求正文、开头、标题或去 AI 味 | 不强行重做内容准备；说明属于后续阶段并交还当前请求，不擅自调用其他 Skill。 |

同行材料可选，不能成为所有任务的入场条件。运行时不读取 `evals/`，其中是制作者的本地测试记录。

## 展示与讨论边界

收到同行文案、用户尚无自己的判断时，第一轮只展示三个结果：

1. **话题**：去掉原作者立场后的讨论领域。
2. **值得讨论的问题**：不夹带未经证实的前提，不把方向限制为赞成、反对或补充同行。
3. **关键事实或现象**：少量值得解释的材料，注明来源与核实状态。作者的结论、因果解释和群体概括不能包装成事实。

围绕其中最重要的问题，邀请用户说出自己的经历、目的、困惑或判断，再继续提炼。用户没有思路时，从具体情境与选择追问；可以提出开放方向，但不沿同行论证路径改写成引导问题。不要求每次收材料都重走此轮讨论。

用户形成初步判断后，将同行作为检验和补充材料。默认只展示影响当前判断的结果，不倾倒拆解表。需要具体评价、反驳，或用户主动要求看同行分析时，展示有关主张和必要原文；也不能借展示限制隐藏会推翻我们观点的关键证据。

这是呈现和讨论顺序的约束，不承诺用户或 AI 能完全不受输入影响。

## 每轮讨论怎样推进

需要通过对话形成观点、澄清含义或检验解释时，读取 [讨论推进规则](references/discussion-flow.md)。已有材料足够交付时直接收束。

每轮先用一两句话回应用户新材料带来的具体判断或变化，再按当前缺口选择一个动作：还原具体情境、澄清模糊评价、提出有依据的暂定解释，或检验已有解释。默认只问一个最能改变判断的问题，回答到来后据此更新，不机械轮询。

只有同行材料时，仍先执行展示边界；用户表达自己的经历、目的、困惑或判断后，再提出解释。AI 每轮也应贡献有依据的辨别、联系或边界，不能只复述后连续追问。无依据时说明能判断到哪里，不为制造新意编造判断。

观点明确、依据能支撑相应范围、关键立场无分歧时交付。还缺决定性事实就保留未知或缩小结论，不通过反复认同把假设升级成事实。

## 工作步骤

### 1. 恢复任务与材料

从当前输入和前文提取目的、受众情境、用户判断、材料及限制。先整理，不先发问卷。

材料多时，识别判断、理由、案例和有辨识度的原话，归并重复，留出无关碎片。修正明确的转写错误；会改变立场的疑点先标注。

材料少时，判断它能支撑多大范围的内容。可提出推理和解释方向，但不能补造事实。已有初稿先提取中心和依据，不仅因为有另一种写法就要求重做。

保留来源信息：用户自述、直接原文、用户转述、外部资料，或 AI 提议。原话与转述不要混排成引文。

### 2. 明确目的与讨论范围

用具体话说明：谁在什么情境下，听完后能多理解什么、改变哪个判断或更有依据地做什么选择。

不以“提供价值、引发共鸣、建立认知”代替目的。没有材料支持时，把受众情境标为工作假设。

从材料中收窄选题，说明本篇讲到哪里。多个目的或碎片无法共同成立时提出主次建议，不静默替换用户的方向。

### 3. 提炼并检验观点

已有明确观点：保留对象、条件、程度和立场，检查依据是否匹配。

尚无明确观点：只有同行材料时，先遵守展示与讨论边界，不直接给出围绕同行结论的候选。已有用户自己的观察、目的或困惑后，提出少量有实质差别的候选。材料只支持一个就只给一个。说明必要依据和缺口，不默认展示整个对照分析。

需要同行对照时执行专用参考中的方法。对照的结果必须转化为本篇能展开的判断或支撑论点，不能停在一张竞品总结表。

对选中的主线检查：

1. 它是事实判断、因果解释、价值选择还是行动建议？不同类型使用相应依据，价值偏好不能伪装成已证实事实。
2. 重要材料分别支持哪一段判断？有哪些从个例跳到普遍、从相关跳到因果、从一个指标跳到整体效果的问题？
3. 什么反例或新证据会迫使我们缩小或放弃判断？现有材料中是否已经存在？
4. 如果证据不足，能够保留的最强、最具体的判断是什么？不要只堆“可能、也许”，应调整实际范围。

仅当差异涉及作者立场、事实或本篇方向时追问。措辞和普通排序自行处理，不为每个建议都设置确认关卡。

### 4. 组织论据，处理缺口

按材料的实际作用整理：支撑判断、解释概念、呈现情境、帮助连接，或值得保留的表达。注明能证明什么和不能证明什么。

出现缺口时优先选择：缩小结论、舍弃非必要支线、用现有材料补足解释；仍会使核心论点无法成立时再追问或核实。

需要外部核实且具备工具时，查证核心事实，记录原始来源、必要日期和适用范围。用户禁止联网时遵守；无法查证就保留待核实状态，不能声称查过。搜索目标是检验命题，包含可能推翻它的证据，不只收集同意材料。

提问要连接具体分歧，例如“这次少掉的是无效咨询，还是实际付费客户也少了？这会决定能否说做法更有效”，不要只问“你有没有案例”。每轮默认只问一个最能改变判断的问题；同一事件中不可拆开的少量事实可一起问，不扩成问卷。

### 5. 找话题入口，完成交接

从目标人群可能关心的较大问题进入，说明它与本篇选题的实际联系。话题入口不能更换中心、捏造集体误解或承诺流量。选题本身足够具体时可以直接进入，不凑大话题。

使用 [内容准备交付格式](references/handoff.md)，按讨论或完成状态只展示关键结果。准备结果应使下游理解“写什么、凭什么、什么不能写”；具体反驳任务再携带必要的对方主张。不提前选正文框架、写完整口播或造开头金句。

## 续接与停止

- 用户补充后更新受影响的判断、证据和写作状态；新证据推翻旧判断时说明变动，不把旧标签静默保留。
- 关键立场待定时，保留候选与关键问题；不要把未选方案交接成已定立意。
- 未证实的反驳不能成为已定事实；必要时只交付可成立的部分或停止该条主线。
- 材料足够就交付；无须等所有栏位填满，不因没有同行材料而停住。
- 无材料时只邀请：“把选题、零碎想法、语音转写或初稿发来，也可以直接发一篇或多篇同行文案，不需要提前整理或想好观点。”
- 默认在对话内交付。只有用户要求保存、制作文件或授权既定文件工作流时才写入；不自动发布或向他人发送。

## 完成标准

目的与中心一致；每个重要判断能追溯到来源和依据；事实、推测、提议与立场可区分；存在同行对照时，分歧具体且双方均经检验；非共识范围没有超出样本；保留作者原话及边界；缺口与下一步可写状态明确。
