# wc：学员内容创作工具箱

根据用户已经提供的任务和材料，选择合适的 Skill，说明需要的输入并给出调用方式。

## 工具清单

整套 wcskill 包含 `wc` 总入口和下表十一个子 Skill，共十二个。展示整套名单时把入口也计入；介绍具体能力时使用下表。

| Skill | 功能 | 需要什么 |
| --- | --- | --- |
| `wc-content-prep` | 内容准备与观点共创 | 素材、经历、观点或同行文案 |
| `wc-author-voice` | 作者思维画像 | 指定作者的多篇文案 |
| `wc-draft` | 短视频正文写作 | 用户材料、确认的框架及可选作者语料 |
| `wc-hook` | 短视频开头生成（试用框架） | 已有正文和内容目的 |
| `wc-check` | 全稿检查与修订 | 完整口播稿或独立稿件 |
| `wc-organize` | 保留各项数据的短视频语料断行整理 | 含正文的短视频 CSV；可补充正文列名、处理范围、是否已经校对 |
| `wc-dy-hook` | 抖音开头分析与生成 | 对标文案与数据表；生成开头时还需要自己的正文和开头范式库 |
| `wc-xhs-title` | 小红书标题生成 | 话题或正文，以及希望吸引的受众 |
| `wc-research` | 思想家圆桌研究、反推知识与持续学习 | 一个问题、主题或内容；可指定人物，或提供原圆桌及反馈 |
| `wc-position` | 人设定位方案 | 产品与客单价、履历、客户认知、竞争环境；代运营可提供定位报告、性格和初步判断 |
| `wc-update` | 更新 wcskill 工具箱 | 直接说“帮我更新 wcskill”；也可只询问版本或更新内容 |

## 路由

- 整理素材、观点、经历或同行文案，形成正文写作依据：使用 `wc-content-prep`。
- 提取指定作者稳定的思维方式、论证逻辑和表达习惯：使用 `wc-author-voice`；内容准备阶段需要作者画像时，可先确认是否调用它。
- 根据材料、已确认框架与可选作者语料写完整口播正文：使用 `wc-draft`。
- 根据已有正文设计开头并衔接正文：使用 `wc-hook`。这是试用框架，部分规则尚待独立窗口验证。
- 检查或修订完整口播稿：使用 `wc-check`；用户明确要求只诊断时不改稿。
- 把短视频 CSV 转成保留数据的气口断行稿：使用 `wc-organize`。该工具仅处理 CSV，不将 Markdown 整理或账号拆解任务路由给它。
- 拆解对标开头、提炼开头范式、给正文写抖音开头：使用 `wc-dy-hook`。
- 小红书笔记起标题、修改标题：使用 `wc-xhs-title`。
- 让多位思想家讨论、研究问题、查理论依据、从内容反推该学什么、系统学习或继续课题：使用 `wc-research`。圆桌追问沿用其中已确认的人物。仅润色成稿、整理素材或管理整个知识库不路由给它。
- 人设定位、账号形象设计、为客户制定或调整人设方案：使用 `wc-position`。交付定位报告，承接已有产品与人群资料。
- “帮我更新 wcskill”“升级 wcskill”：读取 `wc-update` 并执行其中的更新流程，不停在推荐工具或再次确认。只问版本、更新内容或是否需要更新时，进入其只读检查分支。

用户问有哪些工具时展示上表。明确任务后，只推荐当前匹配的工具；已有材料不重复索要，缺少影响执行的必要信息时再问。

## 调用方式

Codex 中用 `$wc-organize` 等名称调用；Claude Code 中用 `/wc-organize` 等名称调用。中文描述任务也可用于匹配对应能力。

WorkBuddy 中直接用中文说明任务，或从已安装的技能列表选择对应 Skill。更新请求进入 `wc-update` 的 WorkBuddy 分支，沿用实际安装目录。

本入口只负责选择工具与说明输入，不替代子 Skill 的处理规则。实际使用前确认对应 `SKILL.md` 已安装或可读取；没有的能力如实说明，不虚构其他工具。
