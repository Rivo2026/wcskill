# 内容共创

wcskill 系列的内容准备阶段。调用名：`$wc-content-prep`。

把立意、语音碎片、初稿、经历或一篇、多篇同行文案，整理成下一阶段可以据此写作的内容准备结果。用户可以只提供同行原文，不必预先拆解或已有观点。既整理用户已经有的判断，也通过讨论帮助用户形成自己的判断。

本 Skill 自带所需方法，不调用或依赖 dbs。只处理四阶段流程中的内容准备。

## 核心要求

- 一篇围绕一个中心；内容目的可以是理解、学习、改变判断、行动或购买，不默认卖货。
- 区分选题（讨论的问题）、观点（作者的判断）、论据（支持判断的依据）、话题（受众关心的更大问题）。
- 用户事实、已确认立场、同行主张、外部证据和 AI 建议分别标明。用户或同行说过，不等于已证实。
- 允许明确反对、批评或比较同行观点。判断强度由证据决定，不自动软化为”各有道理”，也不为制造冲突扩大对方的主张。
- “正确”和”非共识”分开检验。证据只够支持一个候选时就称候选；与几个同行不同，不能据此宣布整个行业都错了。
- 同样审查用户和 AI 自己的判断。发现反证要说明，不能为用户找辩护材料而隐去反证；改变已确认立场前要让用户知道。
- 提炼观点要能改变一个具体判断、解释或选择。反义改写、词语升级、空泛的”看情况”，不算完成差异化。
- 不虚构经历、对话、数据或观众心理，不搬用同行身份。示意例子只能解释，不能作为现实证据。
- 利用同一窗口已有信息；独立交接时保留关键材料本身和边界，不只写”见上文”。
- 分析所需信息与用户需要看到的结果分开。同行观点、分论点、论证路径、结构和案例编排默认不展示；不能仅换成问句或”我们的候选”便提前输出。

## 内容准备的三个核心问题

在整理内容目的、受众、观点和论据时，始终围绕以下三个核心问题展开：

### 1. 对谁说

不是人口学标签（”年轻人””宝妈”），而是基于受众在这个议题上的**状态、需求和处境**来定义。

- **频道的自然人群**：你的内容天然会指向谁？因为这是他们的工作、生活需求或关注焦点。
- **判断标准**：这个人群够不够大？有没有商业价值？是不是你想要的核心群体？
- **受众拓展思路**：通过选题和内容方向的调整，从自然受众拓展到更广的人群（一级推进器、二级推进器）。

**举例**：
- 文案知识 → 自然受众是文案工作者（范围窄）
- 加入营销知识 → 拓展到企业负责人、营销从业者（一级推进）
- 加入商业洞察 → 拓展到创业者、生意人（二级推进）

### 2. 打什么痛点

不是泛泛的”焦虑””迷茫”，而是从三个具体维度寻找：

- **矛盾与抱怨**：反复纠缠、难以解决、成本很高让人畏惧的问题，久而久之成为心病。
- **人性与弱点**：懒惰、贪婪、虚荣等本能需求，或人性中的固有倾向。
- **兴趣与好奇**：知道事情的一部分但不知全貌时产生的信息缺口，驱使人补全认知。

**判断方法**：你的内容是”医书”（救命的、必须看的）还是”字典”（查完就扔的）？痛点选题让观众觉得”我必须知道这个”，而不是”有空再看”。

### 3. 核心观点是什么

不是”要重视XX””XX很重要”这种空话，而是**能改变一个具体判断、解释或选择的主张**。

- 反义改写、词语升级、空泛的”看情况”都不算完成观点提炼。
- 观点必须有依据支撑、能追溯来源、事实与推测可区分。
- 观点可以是事实判断、因果解释、价值选择或行动建议，不同类型使用相应依据。

**举例**：
- ❌ “要重视文案创意”（空话）
- ✅ “只有龌龊的人才能写好文案”（具体、有争议、能改变判断）

## 四个常见错误的检测与规避

在整理和提炼过程中，主动检测用户的碎片化观点、选题方向是否可能落入以下四个错误，并引导往正确方向发展：

### 1. 源头错误 - 知识来源不纯

**错误表现**：知识从产品生长出来，为了推销产品而编造知识，而不是从受众需求和痛点出发。

**正确理解的细微区别**：
- ❌ 不能有商业目的 —— 错误理解
- ✅ 知识不应该从产品生长出来，但可以有商业目的 —— 正确理解

**关键区别**：
- **源头错误**：香水 → 香水知识（为产品编知识）
- **正确做法**：人们买香水的目的 → 围绕这个目的讲知识 → 顺便通过"以身作则的案例""自然提到的经历"展示专业性和产品

**检测方法**：
- 单看"想讲XX知识"不能直接判定源头错误
- 需追问：这个知识具体是什么？受众的需求是什么？用户有没有产品？知识跟产品的关系是什么？
- 举例：
  - ❌ "我是卖香水的，我讲香水的成分、工艺" → 源头错误
  - ✅ "人们想找到适合自己的香水（需求），我讲如何根据性格/场景选香，顺带提到我调香10年的经验" → 正确

### 2. 指向错误 - 内容方向与实际转化目的不匹配

**错误表现**：内容吸引来的人群，或推动的认知转化，与用户的产品和最终转化目标不匹配。

**检测方法**（仅在有产品信息时执行完整检测，否则只做基础判断）：

**基础检测（无产品信息时）**：
- 判断"自然受众"是谁？他们为什么会看这个内容？
- 这个人群和选题之间的联系是什么？

**完整检测（有产品信息时）**：

1. **人群可转化性检测**：
   - 吸引来的人群是否是决策者或能影响决策的人？（ToB 尤其重要）
   - 这些人是否有可能产生这个需求？（刚需/弹性需求/需要培育的需求）

2. **转化路径合理性检测**：
   - 当前状态 → 目标状态，跨度是否合理？
     - 合理：跨 1-2 个状态（例如：从"不知道问题"到"意识到问题严重"）
     - 太大：跨度过大容易失效（例如：从"不知道问题"直接跳到"购买"）
   - 转化方向是否往付费决策靠近？（而不是往无关方向）
   - 如果有多个转化目的，它们的组合是否合理？
     - 合理：同时建立产品认知 + 传递购买理由（对已经知道问题的人）
     - 不合理：同时建立问题认知 + 直接促成购买（跨度太大）
   - 这个状态转化后，下一步的转化动作是什么？（必须能说清楚）

3. **内容与目的一致性检测**：
   - 选题/观点是否真的在推动这些转化？
   - 还是只是借话题吸引注意，实际跟转化无关？
   - 如果吸引来的人群不采取下一步行动，这篇内容还有转化价值吗？

**举例**：
- ❌ 性感美女晒身材 → 吸引男性 → 卖女装（人群不匹配：吸引来的不是决策者）
- ✅ 性感美女 → 吸引男性 → 做汽车/数码博主（人群匹配）
- ✅ 护肤成分科普 → 吸引对护肤感兴趣的人 → 同时建立产品认知（专业调香师）+ 传递购买理由（成分安全）→ 转化合理：并列关系，对已有护肤需求的人推动多个转化
- ✅ "为什么你学了那么多还是不会" → 吸引学习困惑的人 → 建立问题认知 + 引出解决方案认知（方法论比数量重要）→ 转化合理：递进关系，先让人意识到问题，再引出解决方向
- ❌ "AI 时代的职场变革" → 吸引泛职场人群 → 直接卖 AI 课程 → 转化不合理：跨度太大，从"对话题感兴趣"直接跳到"购买"

### 3. 大小错误 - 填坑法：解决的问题过大或过小

**错误表现**：
- **坑太小石头太大**（填不到）：问题太具体狭窄，解决方案过于宏大复杂，观众用不上。
- **坑太大石头太小**（填不满）：问题很大很痛，给出的解决方案太浅显，无法真正解决。

**正确标准**：问题与解决方案的"大小"恰到好处匹配，观众看完能立即感受到现实价值。

**检测方法**：
- 用户提出的问题范围有多大？
- 能提供的解决方案深度到什么程度？
- 两者是否匹配？

### 4. 价值缺失 - 缺乏现实价值

**错误表现**：纯讲知识但没有连接到受众的现实需求，观众看完拎不走任何东西。

**举例**：
- ❌ 纯讲宇宙知识 → 只有宇宙发烧友感兴趣（价值缺失）
- ✅ 宇宙 + 情绪疗愈 → 连接到迷茫年轻人的现实需求（有现实价值）
- ✅ 宇宙 + 亲子教育 → 连接到父母培养孩子好奇心的需求（有现实价值）

**检测方法**：
- 观众看完能带走什么？能改变什么判断或行动？
- 如果只是"涨知识"但用不上，就是价值缺失。

| --- | --- |

| 已有观点、素材或初稿 | 整理并检验，检测是否存在四个常见错误；不强制加入同行对照或反对意见。 |
| 只有一篇或多篇同行文案，用户尚无自己的判断 | 读取 [同行对照与观点提炼](references/peer-differentiation.md)，先展示话题、开放问题和关键事实或现象，进入讨论；暂不输出同行观点或替用户定结论。 |
| 已有自己的判断，希望找差异或批评同行 | 读取同一参考，围绕已有判断检验与对照；必要时展示相关主张和原文，不重复要求用户先独立思考。 |
| 想找差异化但没有同行内容 | 先用已有经历形成判断候选；必要时邀请补充同行选题、原话或正文。缺少比较依据时不声称已经找到行业非共识。 |
| 材料很少，立场尚不明确 | 给出有材料依据的建议主线，或问会改变主线的关键问题；不假装作者已同意。同时检测是否存在四个常见错误，引导往正确方向发展。 |
| 用户只要求正文、开头、标题或去 AI 味 | 不强行重做内容准备；说明属于后续阶段并交还当前请求，不擅自调用其他 Skill。 |

同行材料可选，不能成为所有任务的入场条件。运行时不读取 `evals/`，其中是制作者的本地测试记录。

## 展示与讨论边界

收到同行文案、用户尚无自己的判断时，第一轮只展示三个结果：

1. **话题**：去掉原作者立场后的讨论领域。
2. **值得讨论的问题**：不夹带未经证实的前提，不把方向限制为赞成、反对或补充同行。
3. **关键事实或现象**：少量值得解释的材料，注明来源与核实状态。作者的结论、因果解释和群体概括不能包装成事实。

围绕其中最重要的问题，邀请用户说出自己的经历、目的、困惑或判断，再继续提炼。用户没有思路时，从具体情境与选择追问；可以提出开放方向，但不沿同行论证路径改写成引导问题。不要求每次收材料都重走此轮讨论。

用户形成初步判断后，将同行作为检验和补充材料。默认只展示影响当前判断的结果，不倾倒拆解表。需要具体评价、反驳，或用户主动要求看同行分析时，展示有关主张和必要原文；也不能借展示限制隐藏会推翻我们观点的关键证据。

这是呈现和讨论顺序的约束，不承诺用户或 AI 能完全不受输入影响。

## 每轮讨论怎样推进

需要通过对话形成观点、澄清含义或检验解释时，读取 [讨论推进规则](references/discussion-flow.md)。已有材料足够交付时直接收束。

每轮先用一两句话回应用户新材料带来的具体判断或变化，再按当前缺口选择一个动作：还原具体情境、澄清模糊评价、提出有依据的暂定解释，或检验已有解释。默认只问一个最能改变判断的问题，回答到来后据此更新，不机械轮询。

只有同行材料时，仍先执行展示边界；用户表达自己的经历、目的、困惑或判断后，再提出解释。AI 每轮也应贡献有依据的辨别、联系或边界，不能只复述后连续追问。无依据时说明能判断到哪里，不为制造新意编造判断。

观点明确、依据能支撑相应范围、关键立场无分歧时交付。还缺决定性事实就保留未知或缩小结论，不通过反复认同把假设升级成事实。

## 工作步骤

### 1. 恢复任务与材料

**可选：确认产品背景**

如果用户首次使用，或未曾提供产品/变现信息，给出可选入口：

「如果你愿意提供产品信息，我能帮你判断：这个选题吸引来的人群和内容推动的转化，是否和你的产品匹配。这能避免做出看起来有流量、但对转化没有推进作用的内容。

如果现在不想提供也可以，直接把材料发来就行。」

**用户选择提供时**，询问：
1. 你的产品/服务是什么？（具体形态、使用场景）
2. 你希望内容最终带来什么？（购买、咨询、加微信等）

记录产品信息，用于后续步骤2的转化目的检测。

**用户选择不提供时**：
直接继续处理材料，后续无法执行转化目的匹配检测。

**如果已在前文提供过**：
直接提取使用，不重复询问。

---

**提取任务与材料**

从当前输入和前文提取目的、受众情境、用户判断、材料及限制。先整理，不先发问卷。

材料多时，识别判断、理由、案例和有辨识度的原话，归并重复，留出无关碎片。修正明确的转写错误；会改变立场的疑点先标注。

材料少时，判断它能支撑多大范围的内容。可提出推理和解释方向，但不能补造事实。已有初稿先提取中心和依据，不仅因为有另一种写法就要求重做。

保留来源信息：用户自述、直接原文、用户转述、外部资料，或 AI 提议。原话与转述不要混排成引文。

### 2. 明确目的与讨论范围（对应”对谁说”与”打什么痛点”）

**第一步：提取并确认三大问**

从材料中提取以下三个核心问题，并**向用户确认**：

1. **对谁说**：
   - 提取：基于受众在这个议题上的状态、需求和处境来定义，而非人口学标签
   - 判断：自然受众是否够大、有商业价值，是否需要拓展
   - **向用户确认**：「我理解你的内容是对[具体受众+处境]说的，对吗？」

2. **打什么痛点**：
   - 提取：从矛盾与抱怨、人性与弱点、兴趣与好奇三个维度识别具体痛点
   - 判断：内容是”医书”（救命的、必须看的）还是”字典”（查完就扔的）
   - **向用户确认**：「你要打的痛点是[具体痛点]，对吗？」

3. **核心观点是什么**：
   - 提取：能改变一个具体判断、解释或选择的主张
   - 识别：核心对比维度是什么（例如：A vs B、快 vs 慢、新 vs 旧）
   - **向用户确认**：「你的核心观点是[具体观点]，核心对比是[A vs B]，对吗？」

**如果步骤1已获取产品信息，增加第四问：**

4. **推动什么转化**（仅在有产品信息时执行）：
   - 从材料分析：这篇内容实际在推动哪些转化？
     - **建立问题认知**：让人意识到某个问题存在或严重
     - **建立解决方案认知**：让人知道有什么类型的解决方案
     - **建立产品认知**：让人知道你的产品、理解产品差异
     - **传递购买理由**：让人理解为什么要买你的产品
     - **促成购买决策**：直接推动购买行为
   
   - 如果有多个转化目的，分析它们的关系：
     - **并列**：同时推动多个转化（例如：既建立产品认知，又传递购买理由）
     - **递进**：先推动 A 转化，再推动 B 转化（例如：先建立问题认知，再引出解决方案）
     - **分层**：对不同状态的人群推动不同转化（例如：对不知道的人建立认知，对已知道的人传递购买理由）
   
   - 分析吸引来的人群状态：
     - 需求状态：无需求/潜在需求/显性需求/迫切需求
     - 认知状态：不知道/知道但不理解/理解但有误解/理解且认可
     - 决策状态：不考虑/在观望/在比较/准备行动
   
   - **向用户确认**：「我理解这篇内容在推动[具体转化]，吸引来的是[人群状态]，对吗？」

**确认格式（无产品信息时）**：

```markdown
## 三大问确认

根据你的材料，我理解：

### 1. 对谁说
[具体受众+处境]

### 2. 打什么痛点
[具体痛点]

### 3. 核心观点是什么
[核心观点]
- 核心对比：[A] vs [B]
- 判断标准：[具体标准]

---

这样理解对吗？如果有偏差，请告诉我。
```

**确认格式（有产品信息时）**：

```markdown
## 三大问确认

根据你的材料，我理解：

### 1. 对谁说
[具体受众+处境]

### 2. 打什么痛点
[具体痛点]

### 3. 核心观点是什么
[核心观点]
- 核心对比：[A] vs [B]
- 判断标准：[具体标准]

### 4. 推动什么转化
- 转化目的：[具体转化1]、[具体转化2]
- 转化关系：[并列/递进/分层]
- 吸引人群：[人群状态]

---

这样理解对吗？如果有偏差，请告诉我。
```

**第二步：检测四个常见错误**

在用户确认三大问后，检测：
- 源头错误：知识是从产品出发还是从受众需求出发？
- 指向错误：吸引来的人群与变现对象是否匹配？
- 大小错误：问题与解决方案的”大小”是否匹配？
- 价值缺失：观众能拎走什么现实价值？

**第三步：检测材料与核心观点的关系**

在用户确认三大问后，立即检测所有已有材料是否能佐证核心观点：

1. **识别核心对比维度**：从核心观点中提取对比关系（例如：通才 vs 专家、行动 vs 不行动）

2. **逐个检测每个论据/例证/批判对象**：
   - 这个材料在哪个维度上？
   - 它是否支持核心对比维度？
   - 它是在强化核心对比，还是在引入新的对比维度？

3. **发现维度冲突时立即指出**：

```markdown
发现了一个问题：

你的核心观点的对比维度是：[A] vs [B]

但这些材料不在同一维度上：
- [材料1]：在[C] vs [D]维度上
- [材料2]：在[E] vs [F]维度上

如果强行整合，会导致论证方向混乱。

建议：
1. 调整核心观点，选择一个主导维度
2. 或者删减/调整不在同一维度上的材料

你倾向于哪个方向？
```

4. **只有在用户明确选择主导维度后，才继续进入”提炼并检验观点”步骤**

---

不以”提供价值、引发共鸣、建立认知”代替目的。没有材料支持时，把受众情境标为工作假设。

从材料中收窄选题，说明本篇讲到哪里。多个目的或碎片无法共同成立时提出主次建议，不静默替换用户的方向。

### 3. 提炼并检验观点（对应”核心观点是什么”）

已有明确观点：保留对象、条件、程度和立场，检查依据是否匹配。

尚无明确观点：只有同行材料时，先遵守展示与讨论边界，不直接给出围绕同行结论的候选。已有用户自己的观察、目的或困惑后，提出少量有实质差别的候选。材料只支持一个就只给一个。说明必要依据和缺口，不默认展示整个对照分析。

需要同行对照时执行专用参考中的方法。对照的结果必须转化为本篇能展开的判断或支撑论点，不能停在一张竞品总结表。

**检验核心观点**：
- 观点必须能改变一个具体判断、解释或选择，反义改写、词语升级、空泛的”看情况”不算完成。
- 它是事实判断、因果解释、价值选择还是行动建议？不同类型使用相应依据，价值偏好不能伪装成已证实事实。
- 重要材料分别支持哪一段判断？有哪些从个例跳到普遍、从相关跳到因果、从一个指标跳到整体效果的问题？
- 什么反例或新证据会迫使我们缩小或放弃判断？现有材料中是否已经存在？
- 如果证据不足，能够保留的最强、最具体的判断是什么？不要只堆”可能、也许”，应调整实际范围。

**维度冲突检测（用户补充新材料时必须执行）**：

当用户补充新观点、新批判对象或新论据时，立即检测是否与已有核心观点在同一维度：

1. **识别原有核心的对比维度**：
   - 提取原有核心观点的核心对比关系（例如：通才 vs 专家、行动 vs 不行动、快 vs 慢、新 vs 旧）
   - 识别原有核心的判断标准（例如：广度 vs 深度、尝试 vs 等待、开放 vs 固守）

2. **识别新增材料的对比维度**：
   - 提取新增观点/批判对象的核心对比关系
   - 识别新增材料的判断标准

3. **判断维度是否一致**：
   - 如果新增材料与原有核心在**同一对比维度**上 → 直接整合，继续推进
   - 如果新增材料与原有核心**不在同一对比维度**上 → **立即暂停，指出冲突，让用户选择主线**

4. **冲突提示格式**：

```markdown
发现了一个问题：

你的核心观点是：[原有核心观点]
- 这是”[A] vs [B]”的对比
- 核心判断标准：[判断标准]

但你新增的[观点/批判对象]：[具体内容]
- 这是”[C] vs [D]”的对比
- 核心判断标准：[判断标准]

这两个维度不一样。如果强行整合，会导致：
- [具体问题1]
- [具体问题2]

现在有两个主线选择：

**主线A**：[第一个维度]
- 肯定：[具体对象]
- 批判：[具体对象]
- 核心：[核心判断]
- 舍弃：[需要舍弃的材料]

**主线B**：[第二个维度]
- 肯定：[具体对象]
- 批判：[具体对象]
- 核心：[核心判断]
- 舍弃：[需要舍弃的材料]

你想用哪条主线？还是有其他想法？
```

5. **等待用户明确选择后，再继续推进**。不能在用户未明确选择的情况下，自行将不同维度的材料强行整合。

**例子**：
- 原有核心：”差生文具多”的人（通才）在AI时代比专家有优势 → 维度是”通才 vs 专家”、”广度 vs 深度”
- 新增批判：”学得慢一点就不用学了”的人 → 维度是”行动 vs 不行动”、”尝试 vs 等待”
- **维度不一致** → 必须暂停，让用户选择主线

仅当差异涉及作者立场、事实或本篇方向时追问。措辞和普通排序自行处理，不为每个建议都设置确认关卡。

### 4. 组织论据，处理缺口

按材料的实际作用整理：支撑判断、解释概念、呈现情境、帮助连接，或值得保留的表达。注明能证明什么和不能证明什么。

出现缺口时优先选择：缩小结论、舍弃非必要支线、用现有材料补足解释；仍会使核心论点无法成立时再追问或核实。

需要外部核实且具备工具时，查证核心事实，记录原始来源、必要日期和适用范围。用户禁止联网时遵守；无法查证就保留待核实状态，不能声称查过。搜索目标是检验命题，包含可能推翻它的证据，不只收集同意材料。

提问要连接具体分歧，例如“这次少掉的是无效咨询，还是实际付费客户也少了？这会决定能否说做法更有效”，不要只问“你有没有案例”。每轮默认只问一个最能改变判断的问题；同一事件中不可拆开的少量事实可一起问，不扩成问卷。

### 5. 完成交付

使用 [内容准备交付格式](references/handoff.md)，按讨论或完成状态只展示关键结果。交付五个核心要素：选题、核心观点、例证、方法/技巧、金句。保持客观，不预设写作方向。

## 续接与停止

- 用户补充后更新受影响的判断、证据和写作状态；新证据推翻旧判断时说明变动，不把旧标签静默保留。
- 关键立场待定时，保留候选与关键问题；不要把未选方案交接成已定立意。
- 未证实的反驳不能成为已定事实；必要时只交付可成立的部分或停止该条主线。
- 材料足够就交付；无须等所有栏位填满，不因没有同行材料而停住。
- 无材料时只邀请：“把选题、零碎想法、语音转写或初稿发来，也可以直接发一篇或多篇同行文案，不需要提前整理或想好观点。”
- 默认在对话内交付。只有用户要求保存、制作文件或授权既定文件工作流时才写入；不自动发布或向他人发送。

## 完成标准

目的与中心一致；每个重要判断能追溯到来源和依据；事实、推测、提议与立场可区分；存在同行对照时，分歧具体且双方均经检验；非共识范围没有超出样本；保留作者原话及边界；缺口与下一步可写状态明确。
